# 이평선 백테스트 "추세 점검" — 설계

2026-10-12

## 왜

배지(골든·데드, 과열도)는 **지금 무슨 일이 일어났는지**만 말한다. 그 신호가 **이 종목에서 과거에 쓸모가 있었는지**는 알 수 없다. 위젯은 종목마다 5년치 일봉을 이미 받아 두므로(`DAILY = 5y`), 새 요청 없이 이평선 규칙을 과거에 대 볼 수 있다.

결과는 "사라/팔아라"가 아니라 **과거 통계**로 보여 준다. 한 종목 5년치(약 1,200봉)로는 대부분 "운과 구분 안 됨"이 나오는 것이 정상이다. 그래서 모든 숫자를 **비교 대상과 우연의 범위** 옆에 둔다.

## 사용자가 정한 것

| 질문 | 결정 |
|---|---|
| 무엇을 백테스트하나 | 이평선 방법 — 검토한 6개 중 **1번(20/60 규칙)과 2번(이평 배열 국면)** 을 먼저 |
| 어디에 보이나 | 52주 줄 아래 새 한 줄 **"추세 점검"** |
| 자세한 숫자 | 마우스를 올리면 툴팁 (펼침 패널 아님) |
| 계산 규칙 | 아래 ② 그대로 |

나머지 방법(이격도 분위 · 이평선 지지 판정 · 눌림목 · 변동폭 범위)은 이번 범위 밖이다. 이번에 만드는 확정 봉 판정 · 비용 · 난수 · 가짜 주가 엔진을 그대로 쓰도록 만든다.

## ① 화면

**위치** — `#w52` 바로 아래, 차트(`.chartbox`) 위에 `<div class="trendchk" id="trendCheck" hidden>`.

- 선택한 종목만 계산한다. 5년 일봉 기준이라 기간 탭(1D~3Y)을 바꿔도 값이 같다.
- 지수(코스피 등)도 계산한다.

**줄 모양**
```
정배열·20선↑ · 20선>60선 34일째 · 5년: 구분 안 됨
```

| 조각 | 뜻 |
|---|---|
| `정배열·20선↑` | 2번 — 지금 이평 배열과 20일선 방향. 배열은 `정배열` · `역배열` · `혼조` |
| `20선>60선 34일째` | 1번 규칙의 현재 상태. 20일선이 60일선 아래면 `20선<60선 12일째`. 처음에는 `20/60 보유` · `정리` 였는데, "보유" 가 사용자의 실제 보유(목록 · 상세)와 같은 말이라 선의 위치로 바꿨다(2026-10-14). 일수는 상태가 바뀐 봉부터 `daysAgo` (골든·데드 배지의 "N일 전"과 같은 계산) |
| `5년: 구분 안 됨` | 1번 판정. `나음`(빨강 `UP`) · `못함`(파랑 `DOWN`) · `구분 안 됨`(회색) · `표본 부족`(회색). 연수는 실제로 쓴 기간(`rule.from` ~ `rule.to`)을 반올림한 값이다 — 5년치는 60일선이 생기기까지를 빼도 약 4.7년이라 `5년`, 상장 2~5년 종목이나 이상 봉 뒤부터 쓴 종목은 `2년` · `3년` (최종 검토에서 바꿈 — 짧은 데이터가 "5년" 으로 읽히지 않게) |

- 글자는 9px, 색은 `--mute` (`.w52` 와 같다). 한 줄을 넘으면 말줄임(`…`)으로 자른다 — 340px 폭에서 줄이 늘면 차트가 밀린다.
- 판정 조각만 `<span>` 으로 감싸 색을 입힌다.

**숨기는 경우**
- 선택한 종목의 `dailyCache` 가 없거나 오류일 때 (아직 못 받음 · 실패)
- 쓸 수 있는 확정 봉이 500개(약 2년) 미만일 때

**데이터 이상** — 국내 종목에서 하루 35% 를 넘게 움직인 봉 뒤로 500봉이 안 남으면 줄에 `추세 점검: 데이터 확인 필요` 만 쓰고, 툴팁에 이유를 적는다.

**툴팁 (예시, 숫자는 모양만 보이는 값)**
```

종가로 판단 → 다음 날 종가에 체결 · 왕복 비용 0.25%

지난 기간의 설명입니다 — 10년치로 해 보니 앞 5년 결과로 뒤 5년을 맞히지 못했습니다
배당·세금·환전 제외 · 관심종목은 이미 고른 종목이라 결과가 유리하게 나오기 쉽습니다 · 과거 통계이며 매매 권유가 아닙니다
```

경우별 문구
- 1번 진입 5회 미만: `진입 4회 — 적어서 판정하지 않음` (줄에는 `5년: 표본 부족`)
- 2번 칸을 넓혔을 때: `같은 배열·방향인 날이 적어 배열만으로 봄` 을 "같은 상태였던 날" 줄 앞에 둔다
- 2번 표본 부족: `같은 상태였던 날이 적어 판정하지 않음` (차이 · 범위 줄을 뺀다)
- 지수: 비용 줄에 `지수는 ETF 로 따라간다고 보고 0.10%`
- 판정은 `구분 안 됨` 이지 `효과 없음` 이 아니다 — "이 표본으로는 알 수 없다"는 뜻이다

## ② 계산 규칙

새 데이터는 받지 않는다. `dailyCache[symbol]` 의 `closes` · `times` 만 쓴다. `quotes[symbol].daily` 는 쓰지 않는다 — `loadQuote` 가 마지막 봉을 현재가로 덮거나 오늘 봉을 덧붙인 사본이다. (`dailyCache` 원본은 `loadQuote` 가 `slice()` 로 복사해 쓰므로 바뀌지 않는다.) 고가·저가도 필요 없다.

### 공통

**쓸 수 있는 봉** — `usableSeries(closes, times, domestic)`
1. 마지막 봉은 늘 뺀다. 장중에는 그 봉 종가가 계속 움직인다. 골든·데드 배지(`confirmedCrosses`)와 같은 규칙이고, 대가도 같다 — 하루 늦게 반영된다.
2. 국내 종목(`isDomestic`)만: 하루 등락 |C[i]/C[i−1] − 1| > 35% 인 봉이 있으면 **마지막 그런 봉부터** 쓴다. 국내 가격제한폭(±30%)을 넉넉히 넘었으니 액면분할 · 병합 같은 데이터 이상이다. 해외 종목과 지수는 이 검사를 받지 않는다.
   - 문턱을 30% 가 아니라 35% 로 둔다(구현 뒤 실데이터 확인에서 바꿈). 진짜 상한가 · 하한가 날이 30% 를 조금 넘게 나온다 — 정확히 +30% 도 부동소수로는 0.30000000000000004, 야후 전일 종가가 기준가와 한 틱 달라 +30.2%. 30% 로 두면 에코프로비엠(2023-11-06)이 "3년" 으로 잘리고 한화오션(2024-11-08)이 "데이터 확인 필요" 가 됐다. 0.5주 무상증자(-33%)는 놓친다.
3. 남은 봉이 500개 미만이면 계산하지 않는다. 2번 때문에 줄었으면 `{ error: 'data' }`(데이터 확인 필요), 원래 짧으면 `null`(줄 숨김).

**시점** — 종가 t 로 판단하고(t 까지의 값만 씀) **종가 t+1 에 체결**한다. 수익은 종가 t+1 부터 붙는다. 시가 체결은 쓰지 않는다. 이평선 기울기는 뒤쪽 차분(MA[t] − MA[t−5])만 쓴다.

**이평선** — `sma` 로 쓸 수 있는 봉 전체에 대해 계산한다. 기간은 상수로 고정하고, 사용자가 켠 이평선(`state.maPeriods`)이나 차트 기간과 상관없다.

**비용** (왕복, 사고팔 때 절반씩)

| 대상 | 비용 |
|---|---|
| 국내 종목 (`isDomestic`) | 0.25% |
| 해외 종목 | 0.10% |
| 지수 (`isIndex`) | 0.10% — ETF 로 따라간다고 본다 |

**난수** — 종목 코드를 FNV-1a 32비트로 해시해 시드로 쓰고 `mulberry32` 로 뽑는다. `Math.random` 은 쓰지 않는다 — 볼 때마다 같은 결과가 나와야 한다.

**판정** — 방법마다 정한 통계 하나만 판정한다. 가짜(우연) 분포의 양쪽 끝 밖이면 `나음` / `못함`, 안이면 `구분 안 됨`. 끝의 폭은 무작위 걸음 주가에서 판정이 5% 안팎으로 나오게 맞춘다(1번 1%, 2번 2.5% + 반쪽 조건). 결과를 보고 기간 · 쌍 · 기준을 고르지 않는다.

### 1번 — 20/60 규칙 백테스트

`ruleBacktest(closes, times, short, long, cost, start)` — n = 쓸 수 있는 봉 수.

- `want[i] = MA_short[i] > MA_long[i]`.
- 시작 `start = 59` (60일선이 처음 생기는 봉). 5/20 도 같은 시작을 써서 두 규칙의 기간을 맞춘다.
- 판단 `d[i] = want[i]`. 쓰이는 것은 i = start … n−3 이다 — 종가 n−2 의 판단은 종가 n−1 에 체결되자마자 마지막 날이라 판다.
- 구간 (t, t+1] 의 보유 여부 `p[t] = d[t−1]`, t = start+1 … n−2.
- 현금으로 시작한다: `p[start] = false`.
- 종가 t 에서 `p[t] ≠ p[t−1]` 이면 체결 — 비용 절반을 뺀다.
- 마지막 종가 n−1 에서 들고 있으면(`p[n−2]`) 판다 — 비용 절반.
- 자산 E: E[start+1] = 1 × (p[start+1] ? 1 − cost/2 : 1). 그다음 E[t+1] = E[t] × (p[t] ? C[t+1]/C[t] : 1) 이고, 종가 t+1 에 체결이 있으면 × (1 − cost/2).

**그냥 보유** — 종가 start+1 에 사서(비용 절반) 종가 n−1 에 판다(비용 절반).

**산출**

| 값 | 정의 |
|---|---|
| `total` | E 마지막 / 1 − 1 |
| `cagr` | (1+total)^(1/연수) − 1, 연수 = (times[n−1] − times[start+1]) / 365.25일 |
| `mdd` | 날마다 E 의 직전 최고점 대비 하락폭의 최댓값 (현금 구간 포함) |
| `inShare` | p[t] 가 참인 구간 비율 |
| `entries` | 현금 → 보유 체결 횟수 |
| `trades` | 체결 횟수 (사고 판 것 모두). 5/20 줄의 비용 합계는 renderer 가 trades × cost/2 로 계산한다 |
| 현재 상태 | `want[n−1]` 과, 그 값이 이어진 첫 봉의 시각 |

**판정 — 시점 밀기(회전)**
- 쓰이는 판단 열 `d[start..n−3]` (길이 m = n−2−start) 를 k 칸 돌린다: `d'[start+j] = d[start + (j+k) mod m]`. 보유 비율과 매매 횟수(이음매 ±1)는 같고 시점만 엉뚱해진다.
- k 는 62 … m−62 를 200등분한 값 `k_j = 62 + round(j × (m−124) / 199)`, j = 0…199. 난수를 쓰지 않는다. 62 칸보다 덜 밀면 안 된다 — 20일선과 60일선의 차이는 최근 59일 등락으로만 정해져서, 덜 밀면 가짜 규칙이 자기 구간의 등락을 미리 "본다".
- 돌린 200개를 같은 엔진(같은 비용 · 지연)으로 다시 계산한다.
- 통계: 규칙의 누적 수익이 돌린 200개 중 몇 번째인가 — `pct = (#{작음} + 0.5 × #{같음}) / 200`. 기간이 같아 연 수익 순위와 같고, 그냥 보유는 상수라 "규칙 − 보유" 의 순위와도 같다.
- `pct ≥ 0.99` → 나음, `pct ≤ 0.01` → 못함, 그 사이 → 구분 안 됨. 툴팁에는 순위를 개수로 보인다 — "규칙보다 누적이 낮은 것 #{작음}개" 와 경계 "(198개 이상이면 나음 · 2개 이하면 못함)". 처음에는 "상위 round((1−pct)×100)%" 였는데, 반올림 때문에 "상위 99%" 가 못함에도 구분 안 됨에도 나와 바꿨다(2026-10-13 재검증).
- 끝을 1% 로 둔 이유(2026-10-12 실측): 돌린 200개는 이웃끼리 거의 같아 실제로 독립인 비교가 20개 남짓이다. 2.5% 로 두면 무작위 걸음 600개에서 7.5%(45개)가 나음/못함으로 걸렸고, 1% 에서 5%(30개)였다. 추세가 이어지는 주가(평균 60일마다 오름↔내림)에서는 1% 로도 20개 중 16개가 나음이었다.
- 진입 5회 미만이면 판정하지 않는다 → `표본 부족`.
- 돌린 200개의 `mdd` 중앙값을 툴팁에 함께 보인다.
- 그냥 보유와 바로 판정하지 않는 이유: 덜 들고 있는 전략은 오르는 종목에서 수익이 낮고 낙폭이 작은 것이 당연하다.

**5/20** — 같은 엔진으로 `ruleBacktest(…, 5, 20, cost, 59)` 를 돌려 진입 횟수 · 비용 합계 · 누적만 툴팁 한 줄로 보인다. 판정하지 않는다.

### 2번 — 이평 배열 국면

`maRegime(closes)` — MA5 · MA20 · MA60 · MA120, t ≥ 119 (120일선이 생긴 뒤).

| 배열 | 조건 |
|---|---|
| 정배열 | MA5 > MA20 > MA60 > MA120 |
| 역배열 | MA5 < MA20 < MA60 < MA120 |
| 혼조↑ | 둘 다 아니고 MA20 > MA60 |
| 혼조↓ | 둘 다 아니고 MA20 ≤ MA60 |

- 20일선 방향: MA20[t] > MA20[t−5] 이면 ↑, 아니면 ↓.
- 칸 = 배열 × 방향 → 8칸. 줄에는 혼조↑ · 혼조↓ 모두 `혼조` 로 쓰고, 툴팁에서 "(20일선이 60일선 위/아래)" 로 구분한다.

`regimeStats(closes, times, cost, rng)` — h = 20.
- 날마다 `r(t) = C[t+1+h] / C[t+1] × (1 − cost) − 1` — 다음 날 종가에 사서 20거래일 뒤 종가에 판 수익, 비용 차감. t+1+h ≤ n−1 인 t 만 쓴다(끝나지 않은 창은 뺀다).
- 지금 칸 = t = n−1 의 칸.
- 지금 칸이었던 t 들의 `r` 중앙값 · 오른 비율 vs 모든 t 의 `r` 중앙값 · 오른 비율 → **차이 = 칸 중앙값 − 전체 중앙값**.
- 구간 수: 칸이 끊기지 않고 이어진 덩어리 수. 겹치지 않는 묶음 수: 칸에 든 t 를 차례로 보며 직전에 센 t 보다 h 이상 뒤일 때만 센다.
- **칸 넓히기**: 구간 8개 미만이거나 60일 미만이면 방향을 빼고 배열만으로 다시 본다(한 단계만). 그래도 모자라면 `표본 부족` — 차이와 판정을 내지 않는다.
- **판정 — 가짜 주가**
  - 일간 로그수익률을 정상 블록 부트스트랩(평균 덩어리 10일 — 매 걸음 1/10 확률로 새 위치에서 시작, 끝에 닿으면 처음으로 이어짐)으로 섞어 가짜 경로 200개를 만든다. 첫 종가는 실제와 같다.
  - 경로마다 이평선 · 칸 · 전진수익 · 차이를 처음부터 다시 계산한다. 칸은 **실제 시리즈에서 쓴 칸**(넓혔으면 넓힌 칸)을 그대로 쓴다. 그 칸이 하루도 없는 경로는 건너뛴다. 남은 경로가 100개 미만이면 판정하지 않는다.
  - 범위 끝은 가짜 차이를 줄 세워 위아래로 같은 개수(floor(2.5% × 경로 수), 200개면 5개씩)를 밖에 두는 값이다. 처음 구현은 위쪽 끝을 97.5% 자리(200개 중 196번째)로 잡아 위로 4개만 밖에 남았고, 나음이 못함보다 조금 더 나기 어려웠다(2026-10-13 재검증에서 고침).
  - 차이가 위쪽 끝보다 크고, **앞쪽 절반과 뒤쪽 절반**(쓸 수 있는 t 범위를 반으로 나눔)에서 각각 구한 차이가 둘 다 양수이면 `나음`. 아래쪽 끝보다 작고 둘 다 음수이면 `못함`. 나머지는 `구분 안 됨`. 한쪽 절반에 칸이 없으면 `구분 안 됨`.
  - 툴팁에는 가짜 차이의 2.5% ~ 97.5% 범위를 보인다.

### 묶음 — `trendCheck(symbol, closes, times, { domestic, cost })`

`usableSeries` → `ruleBacktest`(20/60, 회전 판정 포함) → `ruleBacktest`(5/20) → `regimeStats` 를 차례로 부르고, 화면이 쓸 값을 한 객체로 돌려준다. `null`(숨김) 또는 `{ error: 'data' }` 도 그대로 돌려준다. `rng` 는 `mulberry32(seedOf(symbol))`.

## ③ 코드 구조

**새 파일 `backtest.js`** — 계산만 한다(DOM 없음). indicators.js 와 같은 형식이다.
- index.html 이 `indicators.js` 다음, `renderer.js` 앞에서 `<script>` 로 읽는다. 화면에서는 indicators.js 가 만든 전역 `sma` 를 쓴다.
- Node(테스트)에서는 `module.exports` 로 읽히고, `sma` 는 `typeof module !== 'undefined'` 일 때만 `require('./indicators.js')` 로 가져온다. 날짜 계산(`daysAgo`)은 renderer 가 한다 — backtest.js 는 봉 시각만 돌려준다.
- 내보내는 것: 상수(`BT_MIN_BARS = 500`, `BT_JUMP = 0.35`, `BT_START = 59`, `BT_ROTATIONS = 200`, `BT_ROT_EDGE = 0.01`, `BT_ROT_GAP = 62`, `BT_PATHS = 200`, `BT_MIN_PATHS = 100`, `BT_BLOCK = 10`, `BT_H = 20`, `BT_MIN_ENTRIES = 5`, `BT_MIN_EPISODES = 8`, `BT_MIN_DAYS = 60`, `BT_REGIME_START = 119`), `seedOf`, `mulberry32`, `median`, `usableSeries`, `equityOf`, `holdOf`, `ruleBacktest`, `rotationVerdict`, `maRegime`, `cellStats`, `altPath`, `regimeStats`, `trendCheck`.
- 가짜 주가 개수 등은 테스트가 줄일 수 있게 `trendCheck` / `regimeStats` 의 옵션으로 받는다(기본값은 위 상수).

**renderer.js**
- `costOf(symbol)` — 위 비용 표.
- `renderTrendCheck(item)` — `renderDetail` 에서 `renderW52` 다음에 부른다. 줄 글자 · 판정 색 · 툴팁(`title`)을 채운다.
- 캐시 `trendCache[symbol] = { key, result }`, key = 쓸 수 있는 마지막 봉의 시각과 봉 수. 30초 갱신 · `renderDetail` 재호출 때는 캐시를 읽고, 새 확정 봉이 생기거나 처음 볼 때만 `trendCheck` 를 부른다. 관심종목 전체를 미리 계산하지 않는다.
- 줄 · 툴팁을 만드는 문자열 함수는 테스트가 vm 으로 부를 수 있게 renderer 안의 이름 있는 함수로 둔다.

**index.html** — `#w52` 다음에 `#trendCheck`, `.trendchk` 스타일(`.w52` 와 같은 글자 · 색, `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`), `<script src="./backtest.js">`.
