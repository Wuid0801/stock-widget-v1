## 빌드

Node.js 18 이상이 필요합니다 (메인 프로세스에서 전역 `fetch`를 씁니다).

```bash
npm install
npm start
```

첫 실행은 화면 중앙에 340×520으로 뜹니다.

### 설치 파일 만들기

```bash
npm run dist    # dist/KRStockWidget-Setup.exe  (약 90MB, 30초)
```

명령은 이것 하나입니다. 아이콘 생성이 안에 포함되어 있어서 `build/icon.svg` 만 고치면 다음 빌드에 자동 반영됩니다.

> **아이콘을 왜 생성하나**
> Windows 는 상황마다 다른 크기를 씁니다 — 제목표시줄 16px, 작업표시줄 32px, 탐색기 48px.
> PNG 를 넘기면 electron-builder 가 256px 한 종류만 넣어서 작은 크기에서 뭉개집니다.
> 그래서 벡터 원본을 16·24·32·48·64·128·256 각각으로 렌더해 멀티사이즈 `.ico` 를 만듭니다
> (`build/make-icon.cjs`, 이미지 라이브러리 없이 Electron 렌더 캡처 + ICO 컨테이너 직접 조립).

> **왜 서명 단계를 꺼두었나**
> electron-builder 는 exe 아이콘을 넣을 때 `winCodeSign` 아카이브를 받아 푸는데,
> 그 안에 macOS 용 심볼릭 링크가 들어 있어 Windows 에서는 개발자 모드나 관리자 권한 없이
> 압축 해제가 실패합니다. 그래서 `win.signAndEditExecutable` 을 끄고,
> 아이콘과 버전 정보는 `build/after-pack.cjs` 에서 `rcedit` 으로 직접 넣습니다.
> 아이콘은 `make-icon.cjs` 가 만든 `build/icon.ico` 입니다. 이 파일이나 exe 를 못 찾으면 경고 대신 빌드를 멈춥니다 —
> 예전 경로(`dist/.icon-ico`)를 보던 동안 이 단계가 경고 한 줄로 건너뛰어져, 설치본이 "Electron" 이름 · 아이콘으로 나갔습니다.
> 따라서 개발자 모드나 관리자 권한 없이 빌드할 수 있습니다.
>
> 서명되지 않은 exe 라 실행 시 SmartScreen 경고가 뜹니다. 없애려면 코드 서명 인증서가 필요합니다.

## 파일 구조

```
main.js               Electron 메인 프로세스 — 창 생성/상태 저장, 외부 API 프록시(IPC)
quote-session.cjs     KRX·NXT 가격 선택, 세션 판정, 확인된 정규장 종가 비교
indicators.js         화면과 무관한 순수 계산 — RSI · 이동평균 · 크로스 · 캔들 · 추세선
backtest.js           추세 점검 — 이평선 규칙을 지난 일봉에 대 보는 계산 (화면과 무관)
preload.js            contextBridge로 안전한 IPC만 노출
index.html            마크업 + CSS
renderer.js           UI 렌더링, Chart.js, 30초 폴링
build/icon.svg        앱 아이콘 원본 (수정하면 다음 빌드에 자동 반영)
build/make-icon.cjs   icon.svg → icon.ico (16~256px 멀티사이즈)
build/after-pack.cjs  패키징 후 exe 아이콘·버전 정보 삽입
tests/                검증 스위트 (npm test)
.github/workflows/    CI — 앱을 띄우지 않는 스위트만 푸시마다
```

### 보안 구조

- `nodeIntegration: false`, `contextIsolation: true`
- 렌더러는 네트워크에 직접 접근하지 않습니다. 모든 외부 요청은 preload가 노출한 IPC를 통해 메인 프로세스에서만 나갑니다 (CORS 회피 + 권한 축소).
- CSP에 `connect-src 'none'`을 걸어 렌더러의 직접 요청을 차단합니다.
- 외부 API에서 받은 종목명은 escape 후 삽입합니다.

## 상태 저장

`electron-store`로 아래 경로에 저장됩니다.

```
Windows  %APPDATA%\kr-stock-widget\config.json
```

저장되는 항목은 다음과 같습니다.

| 키 | 내용 |
|---|---|
| `bounds` | 창 위치·크기 |
| `watchlist` · `selected` · `timeframe` | 관심종목 목록 · 선택 종목 · 타임프레임 |
| `theme` · `opacity` | 화면 테마와 투명도 |
| `maPeriods` | 표시할 이동평균 기간 |
| `maStyles` | 이동평균선별로 바꾼 색 · 굵기 (바꾼 것만) |
| `alerts` | 알림 사용 여부와 종목별 목표가 |
| `holdings` | 종목별 보유 수량 · 평단가 |
| `chartMode` | 1M·3M 을 캔들과 라인 중 무엇으로 그릴지 (기본 캔들) |
| `indicators` | 보조 지표 켜짐 `{ bb, vwap, volAvg, prevHL, vp, rel }` (기본 모두 꺼짐). 아는 키의 `true` 만 믿는다(`cleanIndicators`) |
| `infoOpen` | 상세의 보유 · 52주 · 추세 점검 세 줄을 펴 둘지 (기본 펼침). 세 줄의 `hidden` 은 각자 그리는 함수가 정하므로, 접기는 손잡이 `#infoToggle` 의 `.off` 와 CSS 형제 선택자로만 숨긴다. 접혀 있으면 손잡이 툴팁이 보이던 줄의 내용을 글자로 미리 보인다(`infoTip`, 갱신마다 다시 씀) |

저장 값을 추가할 때는 renderer.js 의 save() 와 main.js 의 state:set · state:get 세 곳을 모두 고쳐야 하며, `tests/state-contract.mjs` 가 이를 검사합니다.

읽어 온 값은 믿지 않습니다. 시작할 때 모르는 이동평균 기간 · 색 · 굵기는 버리고, 모르는 `chartMode` 는 캔들, 없는 선택 종목은 첫 종목, 이 빌드에 없는 `timeframe` 은 `1D` 로 바꿉니다(`validTimeframe`) — 그대로 쓰면 차트가 매 갱신 예외로 끝나 조용히 빕니다. 기간을 빼거나 이름을 바꾸는 빌드가 나와도 같은 설정 폴더를 쓰는 다른 빌드가 멈추지 않게 하려는 것입니다.

기본값으로 되돌리려면 앱을 종료한 뒤 이 파일을 지웁니다. 예전에는 내용을 `{}` 로 바꾸라고 안내했는데, Windows PowerShell 5.1 의 `'{}' >` 는 UTF-16 으로 저장해 읽지 못하는 파일이 됩니다.

**파일이 깨져 있으면**(끝 쉼표, UTF-16 등) 저장소(conf)가 만들어질 때 `SyntaxError` 를 던져 창 코드가 하나도 돌지 않았습니다 — 위젯이 아예 뜨지 않습니다. 지금은 그 파일을 지우지 않고 `config.broken-<시각>.json` 으로 옮겨 두고(평단가는 이 파일에만 있습니다) 기본값으로 시작한 뒤, 옮겨 둔 이름을 알림으로 알립니다(`openStore`). 메모장 · PowerShell 이 붙이는 UTF-8 BOM 은 깨진 게 아니라 떼고 읽습니다.

## 테스트

```bash
npm test              # 전체 (약 6분)
npm test -- rsi dock  # 이름에 rsi / dock 이 들어간 스위트만
```

`quote-session` · `session-ui`는 저장된 응답과 고정 시계로 네트워크 없이 검증합니다.
나머지 UI 스위트는 실제 앱을 Electron 으로 띄우고 실제 API를 호출합니다. 테스트 전용 설정과 창을 공유하므로 순차 실행합니다.
장 시간에 의존하지 않도록, 장중/장마감처럼 외부 상태에 좌우되는 경로는 해당 값을 강제한 뒤 원복합니다.

### CI

푸시와 PR 마다 **앱을 띄우지 않는 열일곱 개**가 GitHub Actions 에서 돕니다 — `rsi` · `cross` · `candle` · `overlay` · `zoom` · `trend` · `backtest` · `quote-session` · `session-ui` · `dom-contract` · `state-contract` · `net-timeout` · `single-instance` · `index-main` · `chart-fill` · `extended-chart` · `sector`.

이 열일곱 개는 Node 내장 모듈과 앱 파일(`indicators.js` · `backtest.js` · `quote-session.cjs` · `renderer.js` · `index.html` · `main.js`)만 씁니다. **`node_modules` 가 필요 없어 설치 단계가 없고 10초 안에 끝납니다.** 계산 로직을 옮기거나 고칠 때 회귀를 바로 잡으라고 둔 것입니다. 가장 오래 걸리는 것은 `backtest` 입니다(2~5초, 2026-10-12 실측) — 판정이 우연을 "나음"으로 말하지 않는지 무작위 주가 수백 개로 확인합니다.

Electron 을 띄우는 나머지 스무 개는 CI 에서 돌리지 않습니다. 창을 열고 실제 시세 API를 호출하므로 느리고, 장 상태와 상류 응답에 따라 결과가 흔들립니다. 그쪽은 로컬 `npm test` 몫입니다.

> 워크플로는 `TZ: Asia/Seoul` 로 돕니다. `daysAgo` 가 **로컬 자정** 기준으로 달력 일수를 세는데, 러너 기본값인 UTC 로 두면 `cross` 의 "다음 날 00:01 에는 1일" 이 깨집니다. 앱은 보는 사람의 시간대를 쓰는 게 맞으므로 동작은 그대로 두고 CI 쪽을 고정했습니다.

### 왜 나눠 쓰는가

- **Yahoo 한국 시세는 20분 지연입니다.** 실측 결과 세 종목 모두 기준시각이 정확히 20분 전이었고, 삼성전자 기준 3,250원(1.4%) 차이가 났습니다. 그래서 현재가만 Naver 실시간으로 덮어씁니다.
- **Yahoo 검색은 한글 쿼리에 HTTP 400을 반환합니다.** `query1`/`query2`/`lang` 지정/`autocomplete` 모두 실패해서 검색은 Naver를 씁니다.
- **차트·RSI는 Yahoo를 유지합니다.** RSI 는 일봉 종가 기반이라 20분 지연의 영향이 거의 없고(마지막 종가만 현재가로 치환), 비공식 API 의존도를 낮추기 위해서입니다.
  - 단, 야후 일봉의 마지막 봉이 아직 어제인데(장 전 NXT 프리마켓 · 개장 직후 — 20분 지연에 30분 캐시) 실시간이 오늘 거래면 어제 종가를 바꾸지 않고 **오늘 봉을 덧붙입니다**(그날 09:00 KST = 00:00 UTC 로, 이동평균이 UTC 날짜로 짝짓기 때문). 바꾸면 어제 봉의 이동평균 끝점이 오늘 가격으로 틀어져(프리 +3% 면 5일선 약 0.6%) 차트의 어제 캔들(실제 종가)과 어긋났습니다. RSI 는 어느 쪽이든 지금 가격을 따릅니다. 휴장일처럼 실시간 값도 지난 날 것이면 봉을 지어내지 않고 지금처럼 마지막 봉을 맞춥니다.
  - **야후 국내 일봉의 빈 날은 네이버 일봉으로 채웁니다**(`main.js` `fillGaps`). 야후는 국내 종목 일봉을 가끔 하루 통째로 비워 줍니다(종가 · 거래량 `null`). 2025-09-19 와 2026-10-12 는 모든 국내 종목이 비었고 1년이 지나도 채워지지 않았습니다. KODEX 200 은 5년에 21일이 비어 있었습니다(2026-10-13 실측). 그대로 두면 1M 이상 차트에서 그날이 빠지고 이동평균 · RSI · 골든·데드 · 추세선 · 추세 점검이 그날 없이 계산됩니다. 30분봉에는 그날이 있어 1W 차트에서는 보였습니다.
    - 일봉(`1d`) 요청이고 국내 종목(`.KS` · `.KQ`, ETF 포함)이며 오늘보다 앞선 빈 날이 있을 때만, 가장 이른 빈 날 ~ 가장 늦은 빈 날(앞뒤로 10봉씩 더)을 `api.stock.naver.com/chart/domestic/item/<코드>/day` 에 한 번 묻습니다. 날짜가 맞는 빈 봉만 네이버의 시 · 고 · 저 · 종 · 거래량으로 채우고, 시각은 야후 것을 둡니다.
    - 지난 날은 바뀌지 않으므로 받은 봉(오늘 것은 빼고)을 `코드:YYYYMMDD` 로 기억합니다(네이버에도 없던 빈 날은 `null`). 그래서 같은 구멍은 종목마다 한 번만 묻습니다. 요청이 실패하면 기억하지 않고 지금처럼 그날을 뺍니다 — 다음 요청에서 다시 묻습니다.
    - 오늘 칸이 비어 있으면(장 전) 채우지 않습니다. 오늘 봉은 위의 실시간 덧붙이기가 맡습니다.
    - **가격 기준이 다른 종목은 야후 기준으로 맞춥니다.** 네이버는 증자 · 분할 · 분배금을 지난 가격에 반영하고(수정주가) 야후 `close` 는 액면분할만 반영합니다. 그런 일이 있었던 종목은 지난 가격의 기준이 달라, 삼성바이오로직스 2025-09-19 는 야후/네이버가 1.053, KODEX 200 은 1.03~1.10 입니다. 그대로 채우면 그날만 최대 9% 꺼졌습니다(2026-10-13, 국내 60종목 빈 날 158개 중 24개). 그래서 빈 날 앞뒤로 가까운 날 5일씩(오늘 제외)의 야후/네이버 종가 비율 중앙값을 시 · 고 · 저 · 종에 곱합니다. 중앙값이라 빈 날 바로 앞날처럼 야후 값이 어긋난 하루에 끌리지 않습니다. 중앙값이 1% 안이면 기준 차이가 아니라 날마다 한두 틱 다른 잡음이라(같은 날 60종목 0.995~1.008) 네이버 값을 그대로 둡니다. 기준 차이가 0.3~0.9% 인 KODEX 코스닥150 은 그래서 보정되지 않습니다.

### 세션 · 시세 소스 · 폴백

현재가는 네이버의 **KRX·NXT 전용 엔드포인트를 각각 다종목 1회 요청**합니다.
거래소 이름은 엔드포인트로 구분합니다. `stockExchangeType`의 KOSPI/KOSDAQ은
상장 시장이며, NXT 응답에도 같은 값이 있으므로 거래소 판정에 사용하지 않습니다.

- `marketStatus: OPEN`만으로 정규장이라고 판단하지 않습니다.
- 상위 `marketSessionType`의 `regularMarket` / `afterMarket`와 상세 상태를 확인합니다.
- 같은 거래일의 유효한 가격 중 거래 중인 소스를 우선하고, 그 안에서는 거래소 순서(KRX → NXT → 보조)로 고릅니다.
- 거래 중인 소스가 하나도 없으면 그때는 시세 시각이 최신인 값을 씁니다. 종료된 기록의 시각만 실제 종료·체결 시각이기 때문입니다.
- 가격이 더 높은 쪽이나 더 낮은 쪽을 고르는 방식이 아닙니다.
- NXT 직접 응답을 사용할 수 없으면 기존 `overMarketPriceInfo`를 보조로 사용하되 거래소 이름은 추정하지 않습니다.
- 한 거래소 조회가 실패해도 다른 유효한 가격은 유지합니다. 모두 실패하면 Yahoo 지연 시세로 전환합니다.

> **거래 중에는 시세 시각으로 거래소를 고르지 않습니다.** 거래 중인 기록의 `localTradedAt`은
> 체결 시각이 아니라 응답이 만들어진 시각입니다. 2026-09-15 실측에서 두 거래소를 함께 조회하면
> 같은 초 안에서 1ms 미만 차이로 순서가 폴링마다 뒤집혔고(KRX↔NXT 교대), 한 응답 안에서는
> 52µs 차이가 1,000원 차이를 갈랐습니다. 시각으로 고르면 체결이 없어도 표시 가격이 진동합니다.

새 체결이 발생했다는 뜻은 아닙니다.

자동 갱신은 별도로 판단합니다. 관심종목 중 거래 중이거나 상태가 불명확한 종목이
있으면 30초, 확인한 종목이 모두 종료됐으면 5분입니다. 미국 종목도 네이버 해외 시세의 세션으로
같이 셉니다 — 국내 장이 닫힌 저녁에도 미국 프리마켓이 열려 있으면 30초입니다. 시세 누락·조회 실패
(네이버에 없는 미국 종목 포함)는 30초로 재시도합니다.

헤더의 **↻** 는 이 자동 갱신(`pollTick`)을 지금 한 번 돌리고, 다음 자동 갱신은 누른 시점부터 다시 셉니다. 캐시(차트 5분 · 일봉 30분)는 비우지 않습니다 — 현재가와 오늘 봉은 매번 실시간으로 받으므로, 장 마감 후 5분 간격을 기다리지 않게 하는 것으로 충분합니다. 캐시까지 비우면 종목마다 5년치 일봉을 다시 받습니다.

**갱신이 끝난 뒤 5초는 쉽니다**(`REFRESH_REST`, 자동 갱신이 끝난 직후도 포함). 갱신 한 번에 네이버 요청이 3개(지수 · KRX · NXT) 나가고 캐시가 없어서, 쉬는 시간이 없으면 연타할 때마다 곧바로 다시 요청합니다. 비공식 API 라 한도를 모르고, 막히면 20분 지연 폴백으로 넘어가 일봉을 1분마다 다시 받게 되어 오히려 무거워집니다. 쉬는 동안에는 아이콘이 흐려집니다.

↻ 는 버튼이라 드래그 영역 밖에 둡니다(위 주석의 깜빡임 문제). 그래서 세션 표시 위에서는 창을 끌 수 없습니다.

| 전체 | `max` | `1mo` → 봉 크기는 야후가 고름 |

야후에는 3년 구간(`3y`)이 없습니다. 3Y 는 이미 허용된 `5y` 를 받아 마지막 봉에서 달력으로 3년 전 날짜부터 남깁니다(`lastYears`, 그날 봉 포함, UTC 날짜 기준). 상장한 지 3년이 안 된 종목은 받은 만큼 다 그립니다. 캐시된 응답은 고치지 않고 잘린 사본을 씁니다. 그래서 `main.js` 의 허용 목록은 그대로입니다. 일봉이라 이동평균 · 골든/데드 · RSI 의 뜻이 1Y 와 같고, 360일선도 3년 내내 끝까지 그려집니다(5년치 일봉 약 1,219봉 ≥ 730 + 360).

**전체**는 `range=max` 입니다. 야후는 max 면 묻는 봉 크기와 상관없이 기간에 따라 봉 크기를 정합니다(2026-10-14 실측: 삼성전자 2000-01~ 월봉 322개, 코스피 1996-12~ 월봉 359개, LG에너지솔루션 2022-01~ 주봉 248개, AAPL 1984-12~ 분기봉 169개. 응답 17~38KB, 마지막 봉은 오늘 가격). `1d` 로 물으면 일봉용 네이버 빈 날 채우기(`fillGaps`)가 월봉에 끼므로 `1mo` 로 묻습니다 — 그래서 `main.js` 허용 목록에 `max` · `1mo` 가 있습니다. 일봉이 아니라(`daily` 거짓) 이동평균 · 골든/데드 · 추세선 · 확대 · 오늘 봉 맞추기는 1D · 1W 처럼 빠지고, 축은 1Y · 3Y 처럼 연/월입니다(`YEAR_TF`).

Yahoo의 1D 봉은 20분 전에서 끊기므로, 장중에는 현재가를 끝점으로 이어붙여 차트 끝과 표시 가격이 어긋나지 않게 합니다(`intradayEnd`).
- **장이 끝난 뒤에는 확인된 종가로 끝냅니다.** 15:30 에 KRX 는 휴지(`OPEN + break`)가 되고 가격은 NXT 애프터마켓에서 와서 세션이 애프터마켓이 됩니다. 야후는 종가를 거래량 0 인 마지막 봉(이름표 "15:00")으로 싣는데 20분 늦어 15:50쯤 옵니다(2026-10-13 실측: `regularMarketTime` 15:30:12). 장중 조건만 있던 때는 그사이 1D 차트가 20분 전 봉에서 멈췄습니다 — 헤더와 `애프터` 점선만 새 값이었습니다.
- 그래서 확인된 종가(`regularClose`, 정규장 종료 응답에서 잡은 값)가 있으면 그 값을 거래소 종료 시각(`closeTime`, 15:30) 이름표로 덧붙입니다. 야후 종가 봉이 이미 와 있으면 점을 더하지 않고 그 봉 값을 거래소 종가로 맞춥니다 — 둘이 한 틱 다르면 끝이 두 개가 됩니다. ETF(애프터마켓 없음)와 지수(마감 뒤 값이 곧 종가)도 같은 규칙입니다.
- 단일가 · 일시정지처럼 정규장 가격이 멈춰 있고 아직 종가가 없으면 그 가격을 끝에 둡니다. 15:20~15:30 단일가 때 네이버가 어떤 상태를 주는지는 아직 기록하지 못했습니다 — 거래 중으로 오든 멈춤으로 오든 끝점이 남게 했습니다.
- 애프터 · 프리 가격은 이 끝점으로 쓰지 않고, 오늘 가격이 아니면(장 전 · 휴일) 끝점을 붙이지 않습니다.
- 시간외 봉이 붙어 있으면 끝점은 **정규장 마지막 봉** 기준입니다 — 종가 봉 맞추기는 그 봉에, 덧붙이기는 시각 순서대로 그 뒤에 끼웁니다. 애프터 봉보다 뒤("지금" 시각)로 가는 끝점은 붙이지 않습니다. 선이 애프터에서 정규장 값으로 되돌아가기 때문입니다.

#### 1D 시간외 봉

1D 는 프리마켓 → 정규장 → 애프터마켓을 한 줄로 잇고, 정규장 밖 구간은 배경을 옅게 칠합니다(`--ext-band`, `extBandPlugin`). 마우스를 올리면 시각 옆에 `프리` · `애프터` 가 붙습니다. 봉마다 세션은 `main.js` 가 `ext` 로 달아 줍니다(`'pre'` · `'after'`, 정규장은 `null`). 시간외 봉이 없으면 응답에 `ext` 가 없고 예전과 같습니다.

- **미국** — 야후에 `includePrePost=true` 로 묻습니다. 어디까지가 정규장인지는 같은 응답의 `meta.tradingPeriods.regular` 입니다(그 봉들의 날짜 기준 — `currentTradingPeriod` 는 다음 날을 가리킬 때가 있습니다). 야후의 시간외 봉은 빠진 시간이 있습니다 — SOXL 10/13 애프터는 1분봉으로도 05:01~07:15(KST) 사이가 통째로 비어(거래량도 0), 아래 빈 칸 채우기 때문에 그 두 시간이 평평한 선으로 보입니다.
- **국내** — 야후는 `includePrePost` 로도 15:30 까지만 줍니다. 네이버 NXT 분봉(`api.stock.naver.com/chart/domestic/NXT/item/<코드>/minute`)을 그날 프리(08:00~08:50) · 애프터(15:30~20:00) 구간만 `startDateTime` · `endDateTime` 으로 받아 5분봉으로 묶습니다(`bucket5m`). 응답은 프리 8KB · 애프터 19KB 남짓입니다(2026-10-14 실측). 이름과 달리 `accumulatedTradingVolume` 은 그 1분의 거래량입니다. 끝난 구간(지난 날 · 끝난 시각)은 앱이 켜져 있는 동안 기억하고, 진행 중인 구간은 30초만 씁니다(`naverWindow`). ETF 는 NXT 에 없어 빈 응답이고, 네이버가 실패하면 정규장만 그립니다.
- **하루의 시작은 프리마켓입니다.** 국내는 08:00, 미국은 17:00 부터 그날 차트가 되고 전날 차트는 빠집니다. 국내에서 오늘 시간외가 아직 없으면(08:00 전 · 휴장일) 야후 봉의 날을 그립니다. 장 시작 직후 야후가 비어 있어도(20분 지연) 프리 봉은 그립니다.
- **빈 칸 채우기** — 시간외는 거래가 드물어 5분 칸이 군데군데 빕니다(SOXL 애프터 48칸 중 18칸). x축이 봉 순서라 그대로 두면 네 시간이 한 시간 반처럼 눌리므로, 같은 세션 안의 빈 칸을 직전 종가 · 거래량 0 으로 채웁니다(`fillExtGaps`). 세션이 바뀌는 곳은 채우지 않습니다.
- 국내 16:00~18:00 에는 헤더 가격이 KRX 시간외 단일가에서 오고 선은 NXT 라 한두 호가 다를 수 있습니다. `애프터` 점선이 헤더 가격 자리를 표시합니다.
- 1W 이상과 지수는 시간외를 그리지 않습니다.

같은 이유로 **장 시작 직후 20분 동안은 국내 분봉(1D · 1W)이 비어** 빈 응답이 옵니다. 그때는 고장이 아니라는 것과 언제 들어오는지를 알립니다 — `분봉은 09:20쯤부터 들어옵니다 (약 7분 뒤 · 1M 이상은 정상)`. 시각은 네이버가 주는 정규장 시작(`stockExchangeType.startTime`, 수능일처럼 늦게 여는 날은 `1000`) + `YAHOO_KR_DELAY_MIN`(20)이고, 한국 시간으로 셉니다. 남은 시간은 30초 갱신마다 줄어들고, 그 시각이 지났는데도 비어 있으면 `분봉이 늦어지고 있습니다` 로 바뀝니다. 해외 종목은 이 지연이 없어 시각을 대지 않습니다.

1D 외의 탭에서는 상단 등락(일간)과 별도로 **해당 구간의 수익률 배지**(`1Y +230.50%`)를 함께 보여줍니다. 1D는 일간 등락과 같은 값이라 표시하지 않습니다.

## 기능별 동작

### 지수 차트

상단 지수 줄의 코스피 · 코스닥을 누르면 관심종목처럼 **선택**됩니다(`select`). 헤더와 차트가 지수로 바뀌고, 종목 줄을 누르면 돌아옵니다. 지수는 야후 기호(`^KS11` · `^KQ11`)로 `state.selected` 에 들어가 저장되므로 재시작해도 그대로입니다(`validSelection`). 선택 대상은 `selectedItem()` 이 관심종목 또는 지수로 돌려줍니다.

지수 시세는 따로 만들지 않습니다. 이미 30초마다 받는 네이버 지수 값을 종목 실시간 시세 모양으로 바꿔(`indexLive`) `loadQuote` 에 넣으므로 RSI · 52주 · 이동평균 · 1D 끝점 · 오늘 봉 맞추기가 종목과 같은 경로입니다. 지수에는 프리 · 애프터마켓이 없어 장이 열려 있으면 정규장, 아니면 장마감입니다. 네이버 지수를 못 받으면 지수 줄은 숨고, 지수를 보던 중이면 헤더는 야후 값으로 "20분지연" 이 붙습니다. 응답에서 종가 · 등락률이 비거나 0 인 지수는 뺍니다 — 숫자로 바꾸면 0 이 되어 지수 줄에 "코스피 0.00" 이 뜹니다(둘 다 빠지면 줄이 숨습니다).

| 지수에서 다른 점 | 이유 |
|---|---|
| 숫자는 소수 둘째 자리 (`curOf` → `'pt'`) | 원화 규칙이면 7,004 처럼 반올림된다. `money` 는 원화가 아니면 둘째 자리로 쓴다 |
| 업종 · 보유 · 평단선 · 종가대비 · 목표가 알림 없음 | 지수에는 해당 값이 없다(보유 · 목표가는 관심종목에만 입력) |
| ↓ 첫 종목 · ↑ 마지막 종목 | 지수는 목록 밖이라 위아래가 없다 |
| 분봉 대기 안내는 국내처럼 09:20 | 야후 지수 분봉도 20분 늦다(2026-10-02 실측). `isDomestic` 은 폴링 · 알림이 써서 그대로 둔다 |

접힌 상태에서 누르면 종목 줄처럼 선택만 바뀌고, 펼치면 지수 차트가 보입니다. 확대 구간은 대상이 바뀌면 모두 풀립니다.

### 캔들차트

**1M · 3M 에서 캔들로 그립니다.** 몸통은 시가~종가, 세로선은 저가~고가입니다. 색은 상세의 오늘 캔들과 같은 규칙 — 시가보다 오르면 빨강, 내리면 파랑, 같으면 회색입니다. 차트 왼쪽 위의 아이콘 버튼(`#chartMode`)으로 종가 라인과 오갈 수 있고, 선택은 저장됩니다. 아이콘은 지금 모드를 그림으로 보여 줍니다.

> **왜 기간 버튼 줄에 두지 않나**
> 처음에는 `캔들` 글자 버튼을 기간 버튼 줄 맨 앞에 두었는데, 모양이 같아 기간 선택지 하나로 읽혔습니다. 게다가 그 줄의 `.on` 은 테스트 세 개(restore · period · chart-integrity)가 "선택된 타임프레임"을 찾는 선택자라, 토글에 같은 클래스를 주면 그 테스트들이 토글을 집었습니다. 차트 안으로 옮기면서 둘 다 사라졌고, 기간 줄도 약 35px 짧아졌습니다.

나머지 구간은 라인입니다. 창이 340px 라 차트 영역이 약 280px 인데, 1Y(243봉)는 봉 하나가 **1.2px**, 3Y(약 730봉)는 **0.38px** 라 몸통도 꼬리도 구분되지 않습니다. 1D(5분봉)·1W(30분봉)은 분봉이라 "일봉 캔들"과 뜻이 다릅니다. 그 구간에서는 전환 아이콘이 숨습니다. 차트 위에 흐린 아이콘을 띄워 봐야 방해만 되기 때문입니다.

기준은 기간 이름이 아니라 **화면에 보이는 봉 수**입니다(`CANDLE_MAX_BARS` = 70, 3M 의 62~66봉을 덮는 값). 확대하지 않은 화면에서는 1M · 3M 만 캔들이 되고, 1Y · 3Y 를 끌어서 70봉 이하로 좁히면 캔들이 됩니다.

캔들 모드에서는 종가 라인과 고가~저가 밴드를 감춥니다. 꼬리가 이미 고저를 말하므로 밴드는 중복이고, 라인은 캔들 위에 겹칩니다. 이동평균선·추세선·거래량·기준선은 그대로 있습니다.

> **왜 데이터셋을 지우지 않고 감추는가**
> 감춘 밴드가 y축 범위를 잡아 줍니다. 캔들은 캔버스에 직접 그리므로 축이 그 존재를 모릅니다 — 지우면 꼬리 끝이 축 밖으로 나가 말없이 잘립니다(추세선에서 겪은 그 문제입니다).
> 종가 데이터셋도 값만 남겨 둡니다. 호버가 좌표가 아니라 인덱스로 도는 덕에 툴팁과 이동평균 범례가 그대로 동작합니다.

> **왜 bar 데이터셋이 아니라 플러그인으로 그리나**
> 처음에는 캔들을 Chart.js 의 bar 로 올려 봤다가 걷어냈습니다. `BarController.overrides` 가 자기 값 축에 `beginAtZero: true` 를 강제해서, 주가 축의 bar 로 올리면 축이 **0 부터** 시작합니다. 25만원짜리 종목이면 축이 0~30만이 되어 하루 등락이 얇은 띠로 눌립니다. 거래량은 전용 축(`yVol`)이라 드러나지 않던 문제입니다. 그래서 지금은 데이터셋 없이 `beforeDatasetsDraw` 플러그인이 캔버스에 직접 그립니다.

툴팁에는 캔들 모드일 때 `시 279,000` 한 줄이 더 붙습니다. 몸통 색이 시가 대비라, 시가가 없으면 왜 그 방향인지 알 수 없기 때문입니다.

### 끌어서 확대

**3M · 1Y · 3Y 에서** 차트를 끌어 고른 구간을 차트 전체로 펼칩니다(`ZOOM_TF`).

누른 채 좌우로 끌면 반투명 상자(`zoomBoxPlugin`)가 따라오고, 놓으면 그 구간이 펼쳐집니다. **5봉 미만이거나 마우스가 6px 미만으로 움직였으면 확대하지 않습니다**(`ZOOM_MIN_BARS` · `ZOOM_MIN_PX`) — 클릭 · 손떨림과 구분하고, 끌다가 도로 좁히면 취소가 됩니다. 픽셀 기준은 3Y 때문에 있습니다. 봉 하나가 약 0.38px 라 5봉이 2px 남짓이어서, 봉 수만 보면 클릭 · 더블클릭할 때의 손떨림이 확대가 됩니다. 6px 은 1Y 의 5봉 폭이라 3M · 1Y 는 봉 수 기준과 같고, 3Y 는 약 16봉(3주)부터 확대됩니다. 되돌리기는 더블클릭이나 `전체` 버튼입니다. 왼쪽 버튼만 끌기로 치고, 마우스가 지나가거나 휠을 굴리는 것으로는 절대 확대하지 않습니다 — 항상 떠 있는 창이라 마우스가 차트 위를 자주 지나가기 때문입니다.

이벤트는 캔버스 요소(`#chart`)에 한 번만 붙이고(`bindZoom`), 끄는 동안의 움직임과 놓기는 `window` 에서 받아 차트 밖으로 나가도 끝에서 멈춥니다. `drawChart` 는 같은 캔버스에 차트를 새로 만들므로 끄는 도중 30초 갱신이 와도 상자가 끊기지 않습니다. 끄는 도중 ↑↓ · 숫자 키로 종목 · 기간이 바뀌거나, 창 밖에서 버튼을 떼 mouseup 을 못 받으면 끌기를 취소합니다.

**y축은 저절로 그 구간에 맞춰집니다.** x축에 `scales.x.min` / `max` 로 봉 번호를 넣으면, Chart.js 4.5.1 의 `DatasetController.getMinMax` 가 그 범위 밖 점을 건너뛰고 y 범위를 잡습니다. 투명하게 남긴 고가~저가 밴드가 여전히 꼬리까지 범위를 잡아 줍니다. 거래량 축은 최댓값을 직접 넣으므로(`max: maxVol * 4`) 확대 중에는 보이는 구간의 최대 거래량으로 다시 계산합니다 — 그대로 두면 막대가 납작해집니다.

**캔들 기준은 보이는 봉 수입니다**(위 "캔들차트"). 1Y 도 70봉 이하로 좁히면 캔들이 됩니다. `candlePlugin` 의 몸통 폭은 이웃한 두 봉의 픽셀 거리로 정합니다 — 폭 ÷ 전체 봉 수로는 확대했을 때 몸통이 그대로 가늘게 남습니다.

**확대 중에는 지지 · 저항 추세선을 숨깁니다.** 추세선은 "지금"을 말하는 선(최근 5봉을 빼고 만들어 오늘 값 · 돌파를 계산)이고, 정규 데이터셋이라 과거 구간 가격에서 먼 선이 y축을 다시 벌려 확대 효과를 깎습니다. 이동평균선 · ▲▼ 교차 표식 · 평단 점선은 그대로 그리고 구간 밖은 잘립니다. 배지(RSI · 기간 수익률 · 골든/데드 · 돌파 · 수렴)는 전체 기간 기준 그대로입니다.

**확대 구간은 봉 번호가 아니라 날짜로 기억합니다**(`zoom = { start, end }`, `zoomRange`). 30초마다 다시 그리고 다음 날엔 봉이 늘어 번호가 밀리기 때문입니다. 비교는 UTC 날짜로 합니다(`maFor` 와 같은 규칙) — 장중 마지막 봉의 시각은 마지막 체결 시각이라 갱신마다 바뀌어, 시각으로 비교하면 마지막 봉을 넣어 확대해도 다음 갱신에서 그 봉이 빠집니다. 그 구간이 5봉 미만이 되면 전체 보기로 돌아갑니다.

| 동작 | 확대 |
|---|---|
| 기간 버튼 · 기간 단축키 | 기간별로 기억 — 그 기간으로 돌아오면 되살림 (`zoomByTf`, `setTimeframe`) |
| 다른 종목 선택 | 모든 기간의 확대가 풀림 (`clearZooms`) |
| 보던 종목 삭제 | 모든 기간의 확대가 풀림 |
| 캔들/라인 전환 · 테마 · 30초 갱신 · ↻ | 유지 |
| 앱 재실행 | 풀림 (저장하지 않음) |

확대 · 되돌리기는 네트워크 요청 없이 `drawChart(lastChart)` 로 다시 그립니다. `loadChart` 의 다시 그리기 서명에도 확대 구간을 넣어 둡니다 — 그 뒤 첫 갱신에서 차트를 한 번 더 만들지만(hover 범례가 한 번 지워진다), 서명이 늘 화면 상태를 담게 해 캔들 토글 때처럼 서명에 빠져 다시 안 그려지는 일을 막습니다.

### 오늘 캔들

선택한 종목의 **현재가 오른쪽**에 오늘 하루를 **9×22px 캔들**로 그립니다. 몸통은 시가~종가, 세로선은 저가~고가입니다. 시가보다 오르면 빨강, 내리면 파랑(한국 관례), 같으면 회색입니다. 마우스를 올리면 `시 279,000 · 고 283,500 · 저 274,000 · 종 276,500` 이 나옵니다.

**옆의 등락률로는 안 보이는 것을 봅니다.** 등락률은 전일 종가 대비라 시가 대비 흐름이 드러나지 않습니다. 삼성전자 실측(2026-09-22)에서 등락률은 `+0.91%` 인데 시가 279,000 → 276,500 으로 밀린 **음봉**이었고, 윗꼬리(283,500)가 몸통보다 길었습니다. 숫자만 보면 오른 날이고, 캔들을 보면 장중에 올랐다가 되밀린 날입니다.

시·고·저는 국내 · 미국은 네이버 실시간(30초마다 최신), 폴백은 야후 일봉 마지막 봉에서 받습니다 — 가격과 같은 순서입니다. 미국 프리마켓에는 지난 정규장의 시·고·저와 그 종가로 그립니다.

**국내는 통합(KRX + NXT) 시세를 씁니다.** 네이버 응답의 최상위 시·고·저는 KRX 전용인데, NXT(넥스트레이드)는 08:00 에 열려 KRX보다 한 시간 빠릅니다. 그래서 NXT가 먼저 체결된 날은 두 값이 갈립니다 — 삼성전자 2026-09-22 실측에서 시가가 **KRX 283,000 / 통합 279,000** 이었습니다. KRX 기준이면 몸통 6,500원에 윗꼬리 500원인 장대음봉이고, 통합 기준이면 몸통 2,500원에 윗꼬리 4,500원인 작은 음봉입니다. 증권사 차트(삼성증권)가 보여주는 것은 후자라, 네이버가 같이 주는 `integratedPriceInfo` 를 우선 읽고 없을 때만 최상위 값으로 돌아갑니다. 저가도 갈립니다(픽스처 2026-09-15: KRX 246,000 / 통합 245,000).

해외·폴백의 야후 일봉은 KRX 기준입니다. 국내 종목에서 네이버 조회가 실패한 동안에는 캔들 기준이 KRX로 바뀝니다. 종가는 세션이 고릅니다: 정규장 중이면 현재가, 시간외·마감 후에는 확정된 정규장 종가(아직 못 받았으면 현재가). 시간외 가격으로 정규장 캔들의 꼬리가 늘어나면 안 되기 때문입니다. 고가·저가는 마지막에 시가·종가로 한 번 조입니다 — 네이버 고저가 현재가보다 한 틱 늦게 오는 순간에 몸통이 제 꼬리를 뚫고 나가기 때문입니다.

야후가 시가를 주지 않는 종목은 캔들 없이 현재가만 나옵니다. 캔들 높이(22px)는 현재가 줄 높이에 맞춰 둬서 그 줄이 더 두꺼워지지 않습니다.

#### 오늘 봉을 실시간으로 맞춥니다

일봉 차트(1M · 3M · 1Y · 3Y)의 **마지막 봉만** 캔들과 같은 값(종가 · 고가 · 저가)으로 덮습니다. 야후 국내 시세가 20분 지연이라 맞추지 않으면 한 화면이 서로 다른 순간을 가리킵니다 — 2026-09-22 삼성전자 저가가 캔들 274,000 / 고저 밴드 274,500 으로 갈렸습니다. 지연 때문이지 거래소 차이 때문이 아닙니다(그날 통합과 KRX 의 고가·저가는 같았고 시가만 달랐습니다).

덤으로 일봉 차트의 끝점이 헤더 현재가와 어긋나던 것도 사라집니다. 예전에는 1D 만 현재가를 이어붙였습니다.

**마지막 봉이 오늘이 아니면 건드리지 않습니다.** 장 전이나 휴장에는 야후의 마지막 봉이 지난 거래일입니다. 거기에 오늘 값을 쓰면 그날에 없던 고가·저가가 생깁니다. 분봉(1D · 1W)도 대상이 아닙니다 — 마지막 봉이 하루가 아니라 5분·30분이기 때문입니다.

### 삭제 되돌리기

목록의 ✕는 관심종목만이 아니라 **직접 입력한 목표가와 보유 수량·평단가까지 함께** 지웁니다. 지운 종목의 설정이 유령처럼 남지 않게 하려는 것이지만, 평단가는 위젯 밖에서 복원되지 않는 값입니다.

그래서 확인 창으로 매번 막는 대신, 지운 뒤 6초 동안 되돌릴 수 있게 했습니다. 되돌리면 **목록에서의 원래 위치까지** 복구합니다. 마지막 하나만 기억합니다.

- 6초 안에 검색으로 **같은 종목을 다시 추가했으면** 줄은 다시 넣지 않고, 비어 있는 목표가 · 보유만 되살립니다. 다시 추가해도 이 둘은 돌아오지 않으므로 되돌리기로 평단가를 찾을 수 있습니다. 예전에는 같은 종목이 두 줄이 되어 보유 합계가 두 배, 목표가 알림도 두 번이었습니다. 추가가 아직 조회 중일 때 되돌려도 추가 쪽이 이미 돌아온 줄을 확인합니다.
- 보고 있던 종목을 되돌리면 시세를 다시 받은 뒤 **차트를 한 번 더 그립니다.** 되돌리면서 고르는 순간에는 시세가 아직 없어, 이동평균 · 교차 배지 · 색(늘 빨강)이 빠진 차트가 다음 갱신까지 남았습니다.
- 마지막 종목을 지우면 그 종목의 **진행 중인 차트 요청도 버립니다**(`clearChart` 가 `chartSeq` 를 올립니다). 늦게 온 응답이 지운 종목의 차트를 빈 헤더 아래 다시 그렸습니다.

### 화면 — 테마 · 투명도

⚙ 설정 패널의 "화면"에서 조절합니다. 둘 다 저장돼 재실행 시 유지됩니다.

| 항목 | 값 |
|---|---|
| 테마 | 다크(기본) / 라이트 |
| 투명도 | 30 ~ 100%, 기본 74% |

투명도는 **마우스가 벗어났을 때의 진하기**입니다. 마우스를 올리면 항상 100%가 됩니다.

> 슬라이더를 조절하는 동안에는 커서가 위젯 위에 있어 hover 로 또렷해지기 때문에 효과가 보이지 않습니다.
> 그래서 슬라이더를 만지는 중에는 hover 를 잠시 무시해 실제 진하기를 보여주고, 손을 떼면 원래대로 돌아옵니다.

색은 `index.html` 의 CSS 변수 한 곳에서만 정의하고, 라이트는 `[data-theme="light"]` 에서 값만 갈아끼웁니다. 차트(Chart.js)도 그리는 시점에 같은 변수를 읽어가므로 테마를 바꾸면 축·격자·툴팁까지 따라옵니다. 색을 조정할 때는 그 두 블록만 수정하면 됩니다.

상승 빨강 · 하락 파랑 · 실시간 초록처럼 **뜻을 가진 색은 두 테마에서 동일**하게 유지합니다.

### 목표가 알림

⚙ 설정 패널의 "목표가 알림" 섹션에서 설정합니다. **기본은 꺼져 있고, "사용"을 켜야만 동작합니다.**

- 종목별로 상한 / 하한을 넣어두면 **장중에 그 가격을 통과할 때** Windows 알림이 뜹니다.
- 통과하는 순간에만 한 번 알립니다. 목표가를 넘어선 상태로 머무는 동안에는 다시 울리지 않고, 되돌아왔다가 다시 통과하면 그때 또 알립니다.
- 앱을 켤 때 이미 목표가를 넘겨 있어도 울리지 않습니다 (첫 갱신은 기준만 잡습니다).
- 국내 종목은 해당 종목의 거래 중 상태가 확인될 때만 울립니다. 프리·애프터마켓도 포함됩니다.
- 해외 종목은 국내 장과 상관없이 판정합니다. 미국 정규장은 한국 시간 밤이라 국내 장과 겹치지 않습니다 — 예전에는 국내 종목이 모두 닫히면 알림 전체를 꺼서, 국내 종목이 하나라도 있으면 미국 종목 알림이 사실상 울리지 않았습니다.
- "통과" 는 **직전에 판정한 가격**에서 지금 가격으로 넘어간 것입니다(`alertBase`). 화면 가격을 기준으로 쓰면 네이버가 한 번 실패한 사이 뜬 야후 지연가(국내 종목은 이 가격으로 판정하지 않습니다)가 다음 기준이 되어, 같은 통과를 두 번 알리거나(100,500 → 지연 99,800 → 100,600) 놓쳤습니다(99,900 → 지연 100,200 → 100,300). 알림을 꺼 두거나 목표가가 없는 동안에도 기준은 따라가므로, 켜거나 목표가를 넣은 직후에 지난 통과를 뒤늦게 알리지 않습니다.
- 관심종목을 삭제하면 그 종목의 목표가도 함께 지워집니다.

### 보유 종목 · 평가손익

보유는 **상세 화면에서 넣습니다**(`renderHolding`). 종목을 고르면 보유 자리에 `＋ 보유 입력`, 보유 중이면 `10주 · 평단 200,000 · 평가 2,310,000 · +310,000 (+15.50%) ✎` 가 나옵니다. 누르면 같은 자리에 수량 · 평단가 칸이 열립니다. 계좌 연동 없이 직접 입력하는 값입니다.
- 수량과 평단가가 **모두** 0보다 큰 수여야 저장합니다(`holdingFrom`). 아니면 저장하지 않고 칸 아래에 알립니다. 예전에는 설정에서 칸 하나를 비우면 말없이 보유가 지워졌습니다.
- 칸은 쉼표를 보이려고 글자 칸(`type="text"`)입니다. 칸을 벗어나면 `200,000` 으로 다시 씁니다.
- 입력 중인 값은 `holdEdit` 에 글자 그대로 둡니다. 30초 갱신이 `renderDetail` 을 불러도 칸을 다시 그리지 않고(`holdFormFor`), 안내와 함께 다시 그릴 때도 친 값이 남습니다. 다른 종목을 고르면 입력은 취소됩니다. 지수에는 보유 자리가 없습니다.
- 버튼(`data-act`) · Enter · Esc 는 init 에서 `#hold` 에 한 번 답니다. Esc 는 입력 칸 안이라 문서의 Esc(위젯 접기)가 무시합니다.
- 저장 · 삭제는 `setHolding` 하나로 모아 목록 · 상세 · 합계 · 차트(평단 점선은 그리기 서명에 들어 있음)를 함께 다시 그립니다.

설정 패널의 "보유 종목" 섹션은 **들고 있는 종목만** 보이고 고치기 · `✕` 지우기만 합니다. 관심종목 전부가 칸으로 늘어서 있어 무엇을 들고 있는지 알 수 없었습니다. 잘못 넣으면 원래 값으로 되돌리고 알립니다.

목록 줄에는 보유 종목만 이름 아래에 `10주 · 손익 +12.50%`(`holdSub`)가 붙습니다. 이름은 `.name` 에 그대로 두고 따로 붙입니다 — 여러 스위트가 `.row .name` 의 글자를 종목명과 비교합니다.

평단가는 **차트에도 가로 점선**(`평단`)으로 표시됩니다. 축과 무관하게 캔버스에 직접 그리기 때문에, 평단가가 화면에 보이는 가격 범위를 벗어나면 y축을 늘리는 대신 선을 생략합니다. 데이터셋으로 넣었다면 평단가 5만 원 / 현재가 20만 원인 종목에서 차트가 통째로 눌렸을 겁니다.

> 검색 결과는 국내(KOR)와 미국(USA)만 노출합니다. 일본 등 다른 시장은 Yahoo 심볼 접미사를 확신할 수 없어 제외했습니다.

#### 미국 시세는 네이버 해외 시세로 받습니다

예전에는 Yahoo 차트 응답의 `regularMarketPrice` 만 썼습니다. 이 값은 정규장이 끝나면 그 종가에서 멈춰서, 프리 · 애프터마켓의 움직임이 안 보였습니다(2026-10-14 17:03 실측: SOXL 프리마켓 126.20 인데 위젯은 127.57). 헤더도 늘 `20분지연` 이었는데, 야후의 미국 시세는 늦지 않습니다(프리마켓 마지막 분봉이 4초 전, 네이버 지연 표시 `실시간`).

- `main.js` `usRealtime` — 접미사 없는 티커만(`US_RE`) 네이버 자동완성으로 네이버 코드(`SOXL.K`, `AAPL.O`)를 찾고(`naverUsCode`, 업종 조회와 공유 · 앱이 켜져 있는 동안 기억), `polling.finance.naver.com/api/realtime/worldstock/stock/<코드들>` 을 한 번 부릅니다. 국내 조회와 함께 돌고, 한쪽이 실패해도 다른 쪽 시세는 씁니다. `BRK-B`(네이버 `BRK.B`)처럼 코드를 못 찾거나 응답이 빈 종목은 빠지고 렌더러가 Yahoo 로 채웁니다.
- `quote-session.cjs` `normalizeWorldQuote` — 국내와 같은 모양으로 바꿉니다. 최상위 기록이 정규장이고(`marketStatus` `OPEN` = 정규장 거래 중, `CLOSE` = 마지막 정규장 종가), `overMarketPriceInfo` 가 프리(`PRE_MARKET`) · 애프터(`AFTER_MARKET`)입니다.
  - 가격은 정규장 종가로 다시 계산합니다. 프리마켓은 그 종가 대비(네이버가 주는 등락과 같음 — 세 종목 실측), 애프터마켓은 국내처럼 **전일 종가 대비**이고 `종가대비` 줄이 오늘 종가와의 차이입니다. 애프터마켓이 끝나도 마지막 가격과 차이를 유지합니다.
  - "오늘" 은 **미국 거래소 날짜**입니다(`localTradedAt` 의 -04:00 · -05:00 로 셈). 정규장이 한국 자정을 넘기 때문에 한국 날짜로 보면 거래 중인 하루가 둘로 쪼개집니다.
  - 정규장 종가보다 오래된 시간외 기록(전날 애프터마켓)은 쓰지 않습니다.
  - `OPEN` · `CLOSE` 가 아니면 쓰지 않습니다(`null` → Yahoo). 프리마켓 직전(16:57)에 `PREOPEN` 이면서 등락이 `0.00` 으로 지워진 응답을 받았습니다 — 그대로 쓰면 등락이 0% 로 보입니다.
  - 시각 필드(`openTime` · `closeTime`)는 비웁니다. 다른 곳에서 한국 시각(HHMM)으로 읽는데 미국 것은 뉴욕 시각(0930 · 1600)입니다.
- 렌더러: 미국 종목은 **야후 일봉을 건드리지 않고**(오늘 봉 맞추기 · 덧붙이기 없음), 일봉 캐시를 1분으로 둡니다. 야후 미국 일봉은 늦지 않아 RSI 가 그대로 맞고, 프리 · 애프터 가격이 정규장 봉에 들어가지 않습니다. 1D 끝점 맞추기(`intradayEnd`)도 하지 않습니다 — 야후 미국 분봉도 늦지 않고, 그 함수의 날짜 · 종료 시각은 한국 기준입니다. `애프터` · `프리` 점선과 `종가대비` 줄은 국내와 같고, 1D 는 프리 · 애프터 봉도 이어 그립니다("1D 시간외 봉").
- 헤더: 네이버를 못 받아 야후 값이면 `20분지연` 대신 `확인중`(세션을 모름)이고, 툴팁 소스는 `정규장 가격 · Yahoo` 입니다.

> 직접 본 상태는 프리마켓 직전(`PREOPEN`, 10-14 16:57), 프리마켓(`CLOSE` + `PRE_MARKET OPEN`, 10-14 17:08), 애프터마켓이 끝난 뒤(`CLOSE` + 그날 종가 + `AFTER_MARKET CLOSE`, 10-15 09:54)입니다. 끝난 뒤의 네이버 애프터 등락은 그날 종가 대비라 `종가대비` 와 같았습니다(SOXL 103.61, 종가 110.54 → -6.93). 정규장 · 진행 중인 애프터마켓은 같은 모양을 가정해 테스트에 만들어 두었고(`tests/quote-session.mjs`), 실제 응답으로 확인해야 합니다.

> 창을 놓쳤을 때는 위 단축키로 되살릴 수 있습니다.

**저장된 창 위치가 화면 밖이면 버립니다.** 외부 모니터에 둔 채 끄고 그 모니터 없이 켜면 저장된 위치는 화면 밖입니다. Windows 는 지정한 좌표의 창을 화면 안으로 옮겨 주지 않고, 작업표시줄 버튼도 없어 위 단축키로도 위치는 그대로였습니다. 그래서 시작할 때 위쪽 끌기 막대(약 30px)가 어느 모니터 작업 영역과 가로 40px · 세로 20px 이상 겹치는지 보고(`reachable`), 아니면 위치는 버리고 크기만 써서 첫 실행처럼 가운데에 띄웁니다. 접은 채 모니터를 뗀 경우도 같습니다 — 접힌 창은 Windows 가 남은 화면으로 옮기지만 펼 자리는 그대로라, 펼 때 그 자리가 화면 밖이면 크기만 살려 지금 화면의 오른쪽 아래에 폅니다. 실행 중에 모니터를 떼는 것은 Windows 가 창을 옮겨 주고 그 위치가 저장되므로 따로 처리하지 않습니다.

**화면(렌더러) 프로세스가 죽으면 다시 띄웁니다**(`render-process-gone`). 창은 남는데 내용이 없고 ✕ 도 안 먹습니다 — 테두리 없는 투명 창이고 작업표시줄에도 없어, 다시 실행해도 죽은 창이 앞으로 올 뿐이었습니다. 다시 뜬 화면은 펼친 상태로 시작하므로 접혀 있었으면 창도 폅니다(`unfold`, 그대로 두면 접힌 크기에 갇히고 위치도 저장되지 않습니다). 시작하자마자 또 죽으면 끝없이 다시 띄우게 되니 1분 안의 두 번째부터는 되풀이하지 않습니다. 실제로 죽은 기록은 없고 대비용입니다 — GPU 프로세스가 죽는 것은 Chromium 이 알아서 다시 띄웁니다.

위젯은 **한 번만 실행**됩니다(`requestSingleInstanceLock`). 둘이 뜨면 각자 관심종목 전체를 저장해 서로 덮어쓰고 — 한쪽에서 추가한 종목이 다른 쪽 저장에 사라집니다 — 네이버 요청도 두 배가 되기 때문입니다. 켜져 있을 때 다시 실행하면 새 창 없이 끝나고, 떠 있는 창이 숨었거나 최소화돼 있어도 앞으로 나옵니다. 잠금은 userData 경로마다 걸리므로 `--user-data-dir` 로 뜨는 테스트는 켜 둔 위젯과 겹치지 않습니다. `tests/single-instance.mjs` 가 앱을 띄우지 않고 이 연결을 검사합니다.

설치본에서는 **Electron 기본 메뉴를 없앱니다**(`Menu.setApplicationMenu(null)`). 테두리 없는 창이라 메뉴줄은 보이지 않지만 단축키는 살아 있어서, 위젯을 누른 채 `Ctrl+W` 를 누르면 앱이 꺼지고(목표가 알림도 끊깁니다) `Ctrl+M` 은 작업표시줄 버튼 없는 창을 최소화해 숨기고 `Ctrl+R` 은 화면을 새로 띄워 접힌 상태를 어긋나게 했습니다. 개발 실행(`npm start`)은 새로고침 · 개발자 도구 단축키를 쓰도록 그대로 둡니다.

### 이동평균선

**5 · 10 · 20 · 40 · 60 · 80 · 120 · 240 · 360일** 중 원하는 것만 골라 그립니다. ⚙ 설정 패널의 "이동평균선"에서 칩을 눌러 켜고 끄며, 선택은 저장됩니다. 기본값은 `5 · 20 · 60` 입니다 — 9개를 한꺼번에 그리면 작은 차트에서 서로 겹쳐 읽기 어렵기 때문입니다.

일봉 타임프레임(**1M · 3M · 1Y · 3Y**)에만 표시합니다. 1D(5분봉)·1W(30분봉)에 "5일선"을 그리면 이름과 실제가 맞지 않기 때문입니다.

**보고 있는 구간에 비해 너무 긴 기간은 자동으로 빠집니다.** 켜 둔 상태라도 그 타임프레임에서는 그리지 않고, 설정의 칩이 흐리게 표시됩니다. 더 긴 타임프레임으로 바꾸면 다시 나타납니다.

| 타임프레임 | 봉 수 | 그려지는 기간 |
|---|---:|---|
| 1M | 약 22 | 5 · 10 · 20 |
| 3M | 약 66 | 5 · 10 · 20 · 40 · 60 · 80 |
| 1Y | 약 243 | 전부 |

y축이 모든 선을 담도록 늘어나기 때문입니다. 1M 차트의 360일선은 8개월 전 평균이라 거의 수평선인데, y축만 크게 벌려 정작 주가 움직임을 눌러버립니다. 삼성전자 기준으로 1M 차트에서 9개를 모두 그리면 주가가 세로의 **39%**만 차지하지만, 구간에 맞는 3개만 그리면 **69%**가 됩니다.

주가선은 2px·불투명, 이동평균은 1px(20 · 40 · 80은 1.2px)·불투명도 80%입니다. 색이 아니라 굵기로 주가선이 먼저 읽히게 한 것이라, 이동평균을 진하게 해도 위계가 유지됩니다. 주가선 아래 채움도 아래쪽을 옅게 해서 이동평균이 지나갈 자리를 비웠습니다.

**선마다 색 · 굵기를 바꿀 수 있습니다**(설정의 기간 칩 아래, 켜 둔 선만 한 줄씩). 바꾼 값만 `maStyles` 에 `{ [기간]: { color, width } }` 로 담고, 차트 선 · 범례 · 설정 칩이 모두 `maColor` · `maWidth` 로 읽습니다. 고른 색은 두 테마에 같이 쓰고, 바꾸지 않은 선은 테마별 기본색(`--ma-N`)입니다. 굵기는 0.5~3px(`MA_WIDTH_MIN` · `MA_WIDTH_MAX`) — 이보다 가늘면 끊겨 보이고, 3px 은 3M 캔들 몸통 폭입니다. 위의 위계는 기본값의 이야기이고, 주가선보다 굵게 두는 것은 사용자에게 맡깁니다. 움직이는 동안은 `drawChart(lastChart)` 로 다시 그리기만 하고 손을 뗄 때 저장합니다. 불러올 때 `cleanMaStyles` 가 모르는 기간 · 색 형식이 아닌 값 · 범위 밖 굵기를 버립니다.

범례(`5■ 20■ 60■`)는 타임프레임 버튼 아래에 오른쪽 정렬로 붙습니다. 차트 안에 두면 9개일 때 두 줄로 늘어나 150px 중 35px 가까이 잡아먹기 때문입니다. 실제로 그려진 선만 나옵니다.

**차트에 마우스를 올리면 범례에 그 시점의 값이 들어갑니다** (`5 71,340■`). 툴팁에 넣지 않는 이유는 툴팁이 켠 이동평균 수만큼 세로로 늘어나기 때문입니다 — 9개면 약 197px 로 150px 짜리 차트를 통째로 덮었습니다. 툴팁은 날짜·주가·거래량 3줄로 고정하고, 이동평균 값은 차트 밖 범례가 받습니다. 값이 비어 있을 때도 자리를 유지해서, 마우스를 올릴 때 범례가 접히며 차트가 들썩이지 않습니다.

#### 골든 · 데드크로스

가장 최근 교차를 배지로 붙입니다 (`5/20 골든 · 3일 전`). 차트에는 교차 지점에 표식이 찍힙니다 — 골든은 선 아래 ▲, 데드는 선 위 ▼. 보는 쌍은 **5/20 · 20/60** 둘뿐입니다. 60/80 처럼 가까운 기간끼리는 횡보 구간에서 계속 교차해 신호 가치가 없습니다.

**마지막 봉의 교차는 말하지 않습니다.** 장중에는 마지막 일봉의 종가 자리에 현재가가 들어가므로(아래 "왜 일봉을 5년치나 받는가") 그 봉의 이동평균은 30초마다 움직입니다. 종가로 확정되기 전의 교차는 장중에 생겼다 사라질 수 있고, 무효가 되면 다음 날 다시 "오늘"로 뜹니다. 삼성전자 실측(2026-09-22 10:17)에서 라이브 280,000원 기준 MA5 264,200 > MA20 260,875 로 **당일 봉에** 5/20 골든이 잡혔습니다 — 전날 09-21 종가 기준으로는 MA5 257,900 < MA20 259,725 로 미교차입니다. 최근 5봉을 빼고 추세선을 만드는 것과 같은 이유입니다.

대가는 하루 늦음입니다. 당일 교차는 다음 거래일에 `1일 전`으로 처음 뜨고, 배지에 `오늘`은 나오지 않습니다. 배지와 차트 표식은 같은 목록을 쓰므로 한쪽만 숨겨 어긋나는 일은 없습니다.

날짜는 **달력 일수**입니다. 예전에는 `(지금 − 봉 시각) / 86400000` 을 반올림했는데, 일봉의 봉 시각이 09:00(KRX 장 시작)이라 **21:00 을 넘기는 순간 하루가 더 세어졌습니다** — 그날 뚫은 것이 밤에 `1일 전`이 됐습니다. 지금은 날짜끼리 비교합니다. 같은 식을 쓰는 돌파 배지도 함께 고쳤습니다.

> **왜 일봉을 5년치나 받는가**
> 이동평균은 차트 구간보다 앞선 과거가 있어야 첫 점부터 그려집니다.
> 1Y 차트(243봉)에 360일선을 끝까지 그리려면 앞으로 360봉이 더 필요해 최소 603봉이 있어야 합니다.
> 1년치(243봉)로는 5일선조차 전 구간을 채우지 못하고, 2년치(484봉)로도 360일선은 모자랍니다.
> 그래서 5년치(약 1,219봉)를 받습니다.
>
> 5년치는 종목당 약 80KB라 30초마다 받으면 낭비입니다. 일봉은 장중에 마지막 봉만 움직이므로
> **30분 캐시**하고, 현재가는 Naver 실시간에서 따로 받아 덮어씁니다. 화면 갱신 주기는 그대로 30초입니다.
> Naver 조회가 실패해 Yahoo 로 폴백한 동안에는 가격도 일봉에서 오므로 캐시를 1분으로 줄입니다.
> 미국 종목은 늘 1분입니다 — 야후 미국 일봉은 늦지 않아 그대로 RSI 를 맞추고, 현재가로 덮지 않습니다("미국 주식").
>
> **일봉을 받지 못하면** 있던 캐시를 쓰되 낡았다고 표시합니다(`stale`). 실시간이 없어 가격까지 캐시에서 온 경우에는 헤더가 `20분지연 <지금 시각>` 대신 `갱신 실패 <받은 시각>` 으로 바뀝니다 — 예전에는 몇 시간 묵은 값이 정상적인 지연 시세처럼 보였습니다. 실시간이 있으면 가격은 새것이라 그대로입니다.
> 받지 못한 종목은 **5분 쉬고**(`DAILY_RETRY`, main.js 의 `CLOSE_RETRY` 와 같은 간격), 갱신 한 차례에 하나라도 실패하면 캐시가 있는 나머지는 그 차례를 건너뜁니다. 쉬지 않으면 야후가 바로 거절(429)할 때 30초마다 전 종목 5년치를 다시 보냈고, 응답이 멈추면 종목마다 8초씩 기다려 갱신 한 번이 1분을 넘겼습니다(그동안 ↻ 도 먹지 않음). 캐시가 없는 종목은 쉬지 않습니다 — 그 줄은 오류라 다음 갱신에 바로 다시 해 봐야 합니다.

### 거래량

차트 하단에 막대로 표시합니다. 전용 y축의 최댓값을 거래량 최댓값의 4배로 잡아 **아래 1/4만** 쓰게 했고, 옅게(투명도 0.2) 그려 겹치는 주가선·이동평균선이 비쳐 보입니다. 툴팁에는 `거래량 1,234만` 형태로 주가 바로 밑에 붙습니다.

> **그리는 순서.** Chart.js 는 `order` 가 **큰** 데이터셋부터 그립니다(4.5.1: `_sortedMetasets` 를 오름차순으로 정렬한 뒤 뒤에서부터 `_drawDataset`, `node_modules/chart.js/dist/chart.js` 5855 · 6123행). 그래서 아래부터 이동평균(3) · 주가선과 채움(2) · 고저 밴드(1) · 거래량(0) · 추세선(-1) 순으로 쌓입니다. 예전 주석은 반대로 적혀 있었습니다.

### 고가~저가 밴드

종가 라인에 겹쳐 그날의 고가~저가를 옅은 띠로 칠합니다(라인 위에 그려지지만 옅어서 라인이 비쳐 보입니다). 종가만 그리면 하루에 얼마나 흔들렸는지가 안 보이기 때문입니다 — 삼성전자 어느 날은 281,500~284,500을 오갔지만(3,000원, 1.06%) 종가 라인에는 점 하나로만 찍힙니다. 툴팁에도 `고저 281,500 ~ 284,500` 으로 나옵니다.

거래량과 고가·저가 모두 차트 응답의 `indicators.quote[0]` 안에 종가와 함께 이미 들어있던 값이라 **추가 요청이 없습니다.**

```
quote[0]: open, high, low, close, volume
```

### 보조 지표

설정의 **보조 지표** 칩으로 켜고 끕니다(`INDICATORS`, 저장 키 `indicators`). 기본은 모두 꺼짐입니다 — 이동평균 · 추세선과 겹치면 150px 차트가 빽빽해집니다. 켜진 칩은 그 선의 색을 띱니다. 새 요청은 `지수 대비` 의 지수 차트뿐입니다.

| 지표 | 기간 | 계산 | 그림 |
|---|---|---|---|
| 볼린저 밴드 | 1M · 3M · 1Y · 3Y | 20일 평균 ± 2 모집단 표준편차(`bollinger`). 이동평균처럼 5년치 일봉 종가(오늘 봉은 현재가)로 계산해 날짜로 맞춘다(`bandFor`) — 1M 첫 봉부터 그려진다 | 위 · 아래 1px 점선(`--bb-line`) 사이를 옅게(`--bb-fill`). 가운데 선은 `20` 이동평균 칩 |
| VWAP | 1D | 대표가 (고 + 저 + 종) / 3 를 거래량으로 가중해 누적(`vwap`). **정규장 봉만** — 시간외 봉은 빼고 그 칸은 비운다. 거래량 0 인 봉(끼운 끝점 · 야후 종가 봉)은 직전 값을 잇는다 | 1.4px 실선(`--vwap-line`) |
| 거래량 평균 · 급증 | 모든 기간 | 20봉 평균. 일봉 기간은 5년치 일봉 거래량으로(`dailyVolAvg`, 일봉 캐시에 거래량을 같이 둔다), 1D · 1W · 전체는 받은 봉으로 — 1D 시간외 봉과 거래량 0 인 봉은 뺀다(`seriesVolAvg`) | 거래량 축에 1px 선(`--vol-avg`), 평균의 2배(`VOL_SURGE`) 넘는 막대는 진하게(0.55). 툴팁 `거래량 123만 · 평균의 3.1배` |

- **매물대는 근사입니다** — 일봉 하나 안에서 어느 가격에 얼마나 거래됐는지는 모르므로 그날 저가~고가에 고르게 나눕니다. 분봉으로 쌓은 증권사 매물대와는 칸마다 조금 다를 수 있습니다.
- **미국 종목의 지수 대비** — 종목 쪽 마지막 값은 현재가라 프리 · 애프터마켓이면 시간외 가격이고, S&P 500 은 정규장 값입니다. 시간외에는 그만큼 섞입니다.
- **VWAP 가 정규장 봉만인 이유** — 미국 프리마켓은 야후 거래량이 0 이고, 국내 시간외는 NXT 거래량이라 정규장(KRX)과 섞으면 평균가의 뜻이 흐려집니다. 국내는 야후 분봉이 20분 늦어 선도 20분 전에서 끝납니다.
- **범례** — 볼린저는 이동평균처럼 마우스를 올린 시점의 `아래~위` 값만, VWAP 는 추세선처럼 마우스를 안 올리면 마지막 값(지금 평균가)을 보입니다.
- **그리는 순서** — 밴드 · VWAP 는 이동평균과 같은 `order` 3, 거래량 평균선은 거래량 막대와 같은 0 입니다. 밴드는 정규 데이터셋이라 y축이 밴드까지 넓어집니다(밴드 밖으로 나간 봉이 보여야 해서).

### 지지·저항 추세선

**3M · 1Y 에서만** 저점을 잇는 지지선과 고점을 잇는 저항선을 점선으로 긋습니다. 켜고 끄는 설정은 없습니다. 3Y 에는 그리지 않습니다 — 아래 규칙(최근 5봉 제외, 연장 10봉 이하 등)은 3M · 1Y 의 봉 수에 맞춘 값이고 약 730봉에서는 검증하지 않았습니다.

두 선은 굵기(1.6px) · 점선 모양이 같고 밝기도 비슷해서(1.08:1) 색만으로는 어느 쪽이 지지인지 알기 어렵습니다. 어느 선이 무엇인지는 차트 위 범례가 색과 오늘 값으로 알려 줍니다(`지지 248,500▬ 저항 261,000▬`, 아래 "오늘 값과 수렴 시점").

> 한때 선 옆에 선 색 9px 글자(`저항`은 선 위, `지지`는 선 아래)를 붙였다가 뺐습니다(2026-10-07). 차트 위에서 보기 불편했습니다.

추세선은 **맨 위**에 그립니다(`order: -1`). 아래에 깔면 1Y 라인 모드에서 지지선이 주가 채움에 물들고, 같은 주황 계열인 5일선이 저항선을 덮습니다.

한정한 이유는 봉 개수입니다. 1M 은 21봉이라 구간이 짧고, 1D · 1W 는 분봉이라 "추세"라고 부를 구간이 아닙니다.

```
1. 최근 5봉을 뺀 나머지 저가(고가)로 볼록 껍질   Andrew monotone chain
2. 껍질에서 가장 긴 선분                        =  추세선 후보
3. 검사 세 개를 통과해야 그린다
4. 빼둔 5봉이 그 선을 뚫었으면 돌파로 표시
```

#### 최근 5봉은 선을 만드는 데 쓰지 않습니다

이게 이 기능의 핵심입니다. **선을 마지막 봉까지의 껍질로 만들면 그 선은 정의상 절대 뚫리지 않습니다.**

볼록 껍질은 넣어준 점을 전부 감싸고, 위쪽 껍질은 기울기가 왼쪽→오른쪽으로 단조 감소합니다. 그래서 어떤 선분을 앞으로 연장해도 그 뒤의 봉은 반드시 연장선 아래에 놓입니다. 마지막 봉까지 넣으면 오늘 고가도 예외가 아닙니다.

결과는 이렇습니다. 하락 저항선이 10,000까지 내려와 있는데 오늘 12,000까지 급등하면, **선이 다시 계산되어 오늘 고가 12,000에 맞춰집니다.** 여전히 "하락 저항선"으로 보이지만 기울기만 완만해졌을 뿐이고, 돌파했다는 사실은 화면에서 사라집니다. 추세선이 알려줄 수 있는 가장 쓸모 있는 정보를 구조적으로 못 말하던 셈입니다.

그래서 **최근 5봉(약 1주)을 껍질에 넣지 않습니다.** 그 봉들은 선을 만드는 데 참여하지 않으므로 선을 뚫을 수 있고, 뚫렸다는 사실을 말할 수 있습니다.

> 이전 판에서 실측표에 적던 `뚫음 0` 은 측정값이 아니라 **항등식**이었습니다. 어떤 데이터를 넣어도 0 이 나옵니다. 성과처럼 읽히던 숫자라 지웠습니다.

#### 검사 세 개

**통과 못 하면 그 선은 그리지 않습니다.**

| 검사 | 기준 | 이유 |
|---|---|---|
| 구간 | 20봉 이상 | 짧은 선분은 최근 두 봉을 이은 것뿐이라 추세가 아님 |
| 연장 거리 | 선분 끝점이 피팅 창 끝에서 10봉 이내 | 오래된 선분을 끝까지 늘이면 엉뚱한 데를 가리킴 |
| 창끝 이격 | 피팅 창 끝에서 선과 실제값 차이 20% 이내 | 0 을 넘더라도 현재가에서 한참 떨어진 선은 정보가 아님 |

**창끝 이격을 왜 "창 끝"에서 재는가.** 현재가와 비교하면 돌파를 걸러냅니다 — 돌파는 주가가 선에서 멀어지는 일이니까요. 반면 피팅 창 끝은 제외 구간 **앞**이라 돌파가 그 값에 섞이지 않습니다. 그래서 거리 기준을 되살려도 돌파는 그대로 보입니다. 실측(2026-09-08 장중, 10종목)에서 실제로 그려지는 선 8개는 |이격| ≤ 6.50% 이고, 급락 시나리오는 36% · 71% 로 사이가 비어 있어 10~30% 어디를 잡아도 결과가 같습니다. 20% 는 관측 최댓값의 약 3배입니다.

> 이 검사는 나중에 덧붙인 것입니다. 처음엔 "현재가 ±10%" 로 재다가 돌파가 걸러져 빼버렸는데, 그때 같이 사라진 보호 장치가 있었습니다. 급락 종목에서 지지선이 **0 이하**를 가리켜 y축 눈금에 음수 가격이 찍혔고(92% 급락에서 오늘값 -1,224), 돌파 판정도 부호가 뒤집혀 이탈이 아닌 봉을 "지지 이탈 +686%" 로 보고했습니다. 0 이하는 아예 거부하고, 나머지는 이 창끝 이격으로 막습니다.

연장 거리 제한은 예전의 "현재가 대비 ±10%" 검사를 대체한 것입니다. ±10% 로는 **돌파를 그대로 걸러내 버립니다** — 돌파하면 선이 현재가에서 멀어지니까요. 원래 막으려던 건 "1Y 저항 +75%" 같은 경우였고, 진짜 원인은 거리가 아니라 **오래된 선분을 멀리까지 연장한 것**이었습니다.

실측으로 재보면 둘이 깨끗하게 갈립니다 (2026-09-08 장중, 6종목 × 3M·1Y):

| 선의 종류 | 연장 거리 |
|---|---|
| 오늘값이 현재가 근처인 멀쩡한 선 | 0 · 0 · 3 · 3 · 4 · 8 · 8 봉 |
| 오늘값이 현재가 대비 +42 ~ +115% 인 엉뚱한 선 | 16 · 16 · 16 · 26 · 39 · 43 · 55 · 56 · 94 봉 |

8봉과 16봉 사이가 비어 있어 **8~15 어디를 잡아도 결과가 같습니다.** 가운데인 10 을 씁니다.

지지선만, 저항선만, **또는 둘 다 없는 상태가 정상입니다.** 안 보이는 것보다 그럴듯한데 틀린 숫자가 나쁘기 때문에, 애매하면 그리지 않는 쪽을 택했습니다.

선은 그 선분의 시작점부터 마지막 봉까지만 그립니다. 뒤로 늘이지 않는 건 화면 밖으로 나가며 y축만 넓히기 때문이고, 앞으로 연장하지 않는 건 카테고리 축에 미래 칸이 없기 때문입니다.

#### 두 가지를 실측으로 바로잡았습니다

**스윙 피벗이 아니라 (피팅 창의) 모든 봉으로 껍질을 쌓습니다.** 처음에는 좌우 n 봉 극값(피벗)만 넣었는데, 피벗이 아닌 봉이 선 아래로 삐져나왔습니다 — 삼성전자 3M 에서 **20봉 중 3봉이 최대 17,871원까지 뚫었습니다.** 껍질이 감싸는 건 넣어준 점들뿐이라, 창 안의 모든 봉을 넣어야 "창 안에서는 뚫리지 않는다"가 성립합니다. 창 밖(최근 5봉)에서 뚫리는 건 의도한 것이고, 그게 돌파입니다.

**마지막 선분이 아니라 가장 긴 선분을 씁니다.** 볼록 껍질은 기울기가 단조라 **마지막 선분이 언제나 가장 가파릅니다.** 그걸 앞으로 연장하니 지지선이 주가 위로 올라갔습니다(기울기 +4,093원/봉, 오늘값이 현재가보다 2,714원 높음). 지지선이 현재가 위에 있으면 이미 뚫린 선입니다.

#### 돌파

빼둔 5봉 중 고가가 저항선 위로(저가가 지지선 아래로) **1% 넘게** 나간 봉이 있으면 배지가 붙습니다.

```
저항 돌파 +8.46% · 1일 전
```

**날짜와 폭의 기준이 다릅니다.**

| | 기준 | 뜻 |
|---|---|---|
| 날짜 | 창 안에서 문턱을 **처음 넘은 확정 봉** | 언제 뚫었나 |
| 폭 | **마지막 봉** 기준 이격 | 지금 선에서 얼마나 떨어져 있나 |

**판정에서 마지막 봉은 뺍니다.** 그 봉의 고가·저가는 장중에 실시간 값으로 계속 덮이므로(위 "오늘 봉을 실시간으로 맞춥니다"), 넣으면 배지가 장중에 떴다 사라지고 무효가 되면 다음 날 또 뜹니다. 크로스 배지와 같은 이유입니다. 그래서 당일 돌파는 다음 거래일에 `1일 전`으로 처음 뜨고, 배지에 `오늘`은 나오지 않습니다. 폭은 그대로 마지막 봉에서 재는데, 그건 사건이 아니라 "지금 얼마나 벗어나 있나"라는 현재 상태이기 때문입니다.

한 봉에서 둘 다 뽑으면 안 됩니다. 예전에는 이탈이 가장 큰 봉 하나를 골랐는데, **저항선은 내려가고 주가는 오르니 초과폭이 날마다 커져 늘 최근 봉이 뽑혔습니다.** 그래서 "N일 전"이 뚫은 날을 가리키지 못했습니다 — SK하이닉스 실측(2026-09-11)에서 09-07 에 뚫었는데 배지는 09-10 을 가리켰습니다.

```
  날짜    고가        선          초과      비율
  09-07   1,783,000   1,656,388   126,612    7.64%   ← 뚫은 날
  09-08   1,889,000   1,629,776   259,224   15.91%
  09-09   1,883,000   1,603,163   279,837   17.46%
  09-10   1,890,000   1,576,551   313,449   19.88%   ← 예전 구현이 고르던 날
  09-11   1,827,000   1,549,939   277,061   17.88%   ← 폭은 여기서 뽑는다
```

지금은 `저항 돌파 +17.88% · 4일 전` 로 나옵니다. 뚫었다가 되밀렸으면 폭이 음수로 나옵니다.

양쪽이 다 뚫렸으면 더 크게 벗어난 쪽만 보여줍니다 — 폭 340px 에 배지가 셋 이상 들어가면 줄이 접힙니다. **돌파가 있으면 수렴 배지는 뜨지 않습니다.** 한쪽이 이미 끝난 선인데 두 선이 만나는 시점을 말하면 틀린 정보입니다.

1% 문턱이 있는 이유는 껍질이 원래 선에 닿기 때문입니다. 스치는 일이 흔해서, 실측에서 Apple 3M 저가가 지지선을 **0.035%(11센트)** 스쳤습니다. 그대로 두면 배지에 `지지 이탈 +0.04%` 가 찍힙니다. 실제 돌파는 2.60% · 4.16% · 8.46% 로 나와 0.5~2% 어디를 잡아도 같은 결과라 1% 를 씁니다.

> **돌파 표시는 뚫은 뒤 4봉(약 1주)까지만 뜹니다.** 5봉이 지나면 그 봉이 피팅 창으로 들어와, 선이 그 봉을 지나도록 다시 잡힙니다. 오래된 돌파는 이미 새 추세의 일부라고 보는 쪽입니다.

다시 잡힌 선도 오름세가 이어지면 다음 봉이 또 넘습니다. 예전에는 그걸 새 돌파로 보고했습니다. 그래서 배지가 몇 주씩 켜진 채 날짜가 늘 `4일 전`(주말이 끼면 `6일 전`)에 머물렀습니다. 합성 시세로 재 보면 배지가 켜진 구간의 약 53%가 4봉보다 길었습니다.

지금은 **한 봉 전 계산에서 돌파로 잡은 봉 위로 선이 다시 그어졌으면(`to` ≥ 그 봉) 배지를 끕니다.** 선은 다시 잡힌 대로 그리고, 배지만 끕니다. 한 봉 전 결과는 이 검사를 거치지 않은 값입니다. 그래서 움직임이 이어지는 동안은 계속 꺼져 있고, 멈춘 뒤 새로 뚫으면 다시 뜹니다(`tests/trend.mjs` 16번).

#### 실제로 얼마나 뜨는가

2026-09-08 장중 측정입니다. 봉이 바뀌면 값도 달라지므로 그 시점의 스냅샷으로 보세요 — 같은 날 장 마감 뒤 다시 재보니 삼성전자 3M 저항이 274,593 → 260,023 으로 움직였습니다.

|---|---|---|---|---|
| 삼성전자 | 3M | 숨김 | 274,593 | — |
| SK하이닉스 | 3M | 숨김 | 1,617,359 | 저항 돌파 +8.46% · 1일 전 |

**지지선이 거의 안 뜨는 건 버그가 아닙니다.** 지금 시장이 크게 눌렸다 되돌린 V자 구간이라 아래 껍질의 최장 선분이 하락 구간을 가리키고, 그 선분의 끝점이 한참 과거(16~26봉 전)에 있어 연장 거리 검사에 걸립니다.

**1Y 가 대부분 숨는 것도 예상된 결과입니다.** 삼성전자가 1년에 71,100 → 374,500 까지 갔다가 되돌린 종목이라 전 구간 직선이 성립하지 않습니다.

> 즉 지금 시장에서 이 기능은 사실상 **"3M 저항선"** 하나로 동작합니다. 횡보 구간이 나오면 지지선도 뜹니다. 자주 안 뜨는 것이 설계 의도입니다 — 못 믿을 선을 그리느니 비워둡니다.

#### 오늘 값과 수렴 시점

두 선 다 `y = y₁ + m(i − x₁)` 꼴이라 오늘 값도 만나는 지점도 바로 나옵니다.

**오늘 값**은 범례에 늘 떠 있습니다. 마우스를 올리면 그 시점 값으로 바뀌고, 벗어나면 마지막 봉으로 돌아옵니다.

```
5 71,340■   20 70,120■   지지 248,500▬   저항 261,000▬
```

**수렴 시점**은 RSI·크로스 배지 옆에 붙습니다.

```
20/60 골든 · 3일 전     수렴 12거래일 · 약 2주
```

다음을 조심해야 합니다.

- **"며칠"이 아니라 "몇 거래일"입니다.** x축이 봉 인덱스이고 3M·1Y는 일봉이라 거래일이 단위입니다. 달력 환산은 7/5 배로 괄호에만 적고, **공휴일은 반영하지 못합니다.**
- **기준은 마지막 봉입니다.** Yahoo 일봉에는 오늘 봉이 장 시작과 함께 생기므로, 장중·장후에 보면 `수렴 1거래일` 은 **다음 거래일**을 뜻합니다 — 금요일이면 월요일입니다. 장 시작 전에는 마지막 봉이 어제라 같은 값이 오늘을 가리킵니다.
- **올림입니다.** `n거래일` 은 "마지막 봉에서 n 번째 봉 안에 만난다"입니다. 반올림하면 0.6봉(거의 붙음)과 1.4봉(다음 봉에도 안 만남)이 똑같이 1 로 나옵니다.
- **수렴할 때만 표시합니다.** 벌어지는 중이면 교차점이 마지막 봉보다 앞(과거)으로 나오는데, 그건 "이미 지났다"가 아니라 값 자체가 의미 없는 경우라 배지를 숨깁니다. 250거래일을 넘어도 숨깁니다 — 사실상 평행선입니다.
- **두 선이 다 통과해야 뜹니다.** 한쪽이 검사에 걸려 숨으면 수렴 배지도 없습니다. 위 실측 기준으로는 지금 어느 종목에서도 뜨지 않습니다.
- **돌파가 있으면 안 뜹니다.** 한쪽이 이미 끝난 선인데 두 선이 만나는 시점을 말하면 틀린 정보입니다.
- **값이 날마다 튈 수 있습니다.** 새 저점 하나가 껍질의 최장 선분을 통째로 바꿔서, 어제 20거래일이던 게 오늘 6거래일이 될 수 있습니다. 추세선의 성질이지 버그가 아닙니다. 다만 최근 5봉은 피팅에 안 들어가므로 **장중 갱신(5분)에는 값이 움직이지 않습니다** — 봉 하나가 피팅 창에 새로 들어올 때만 바뀝니다.
- **교차점은 그리지 않습니다.** 카테고리 축에 미래 칸이 없어 숫자로만 말합니다. 빈 라벨을 붙여 연장하면 기존 봉이 전부 좁아집니다.

> 캔버스에 직접 그리지 않고 **정규 데이터셋**으로 넣습니다. `hLinePlugin` 방식은 y축 범위에 참여하지 않아 선이 말없이 잘립니다 — 시간외 기준선에서 이미 겪었고, 기울어진 추세선은 양 끝이 범위를 벗어나기 더 쉽습니다.

### 보유 종목 합계

보유 수량·평단가를 넣은 종목이 하나라도 있으면 지수 줄 아래에 합계 줄이 뜹니다(`folioLines` · `renderFolio`).

```
보유 3종목  평가 12,345,600            손익 +1,234,500 (+11.10%)
   ↓ 4초마다 (마우스를 올리면 멈춤)
삼성전자 10주  평가 2,310,000           손익 +310,000 (+15.50%)
   ↓
…다음 종목 → 다시 합계
```

- 숫자마다 `평가` · `손익` 이름표를 붙입니다. 예전 줄(`보유 3종목  12,345,600  $1,409  +1,234,500`)은 어느 숫자가 무엇인지 적혀 있지 않았고, 환율 `$1,409` 가 달러 금액처럼 보였습니다. 환율은 툴팁으로 옮겼습니다.
- 보유가 둘 이상이면 합계 → 종목마다 한 줄(목록 순서)로 `FOLIO_MS`(4초)마다 넘어갑니다. 무엇이 합계에 들어갔는지 보이게 하려는 것입니다. 30초 갱신에도 보던 차례(`folioAt`)를 지킵니다. 툴팁에는 모든 줄과 환율이 함께 있습니다.
- 보유가 하나면 그 종목 줄만 보입니다 — "보유 1종목" 으로는 무엇을 들고 있는지 모릅니다. 종목 줄은 그 종목 통화(미국 주식은 달러)로 씁니다.

달러 종목이 섞여 있으면 합계는 원화로 환산해서 더합니다. 환율은 Yahoo 의 `KRW=X` 를 30분 캐시해 쓰고, **둘 이상을 더하는데 외화가 있을 때만** 요청합니다. 환율을 못 받으면 틀린 합계를 내놓는 대신 그 사실을 표시합니다(종목 줄은 그대로 넘어갑니다).

우하단으로 접은 상태에서도 계속 보입니다.

### RSI 과열도

일봉 종가로 RSI(14)를 Wilder 방식으로 계산해 5단계로 표시합니다. 색은 한국 관례(상승 계열=빨강, 하락 계열=파랑)를 따릅니다.

| RSI | 상태 | 색 |
|---|---|---|
| ≥ 80 | 극과열 | 진한 빨강 |
| 70 ~ 80 | 과열 | 주황 |
| 45 ~ 70 | 안정 | 초록 |
| 30 ~ 45 | 주의 | 주황 |
| < 30 | 과매도 | 파랑 |

리스트 각 행의 색 점과 차트 위 배지(`과열 · RSI 72`)로 표시됩니다.

### 추세 점검

52주 줄 아래 한 줄(`#trendCheck`)과 툴팁입니다. 계산은 `backtest.js`, 그리기는 `renderTrendCheck` 입니다. 설계와 결정 배경은 `docs/superpowers/specs/2026-10-12-ma-backtest-design.md` 에 있습니다.

**무엇을 계산하나**
- **20/60 규칙** — 20일선이 60일선 위면 보유, 아래면 정리. 누적 · 연 수익 · 최대 낙폭 · 보유 비율을 그냥 보유와 나란히 보입니다. 5/20 은 진입 횟수 · 비용 합계 · 누적 한 줄만 보입니다.
- **이평 배열 국면** — 5·20·60·120일선 배열 4가지 × 20일선 방향 2가지 = 8칸. 오늘과 같은 칸이었던 날들의 20거래일 뒤 수익 중앙값을 모든 날과 견줍니다. 칸에 구간이 8개 미만이거나 60일 미만이면 방향을 빼고 배열만으로 봅니다.

**미래 값을 쓰지 않습니다**
- 마지막 봉은 늘 뺍니다. 장중에는 그 종가가 계속 움직입니다 — 골든 · 데드 배지(`confirmedCrosses`)와 같은 이유이고, 대가도 같아서 하루 늦게 반영됩니다.
- 종가 t 로 판단하고 **종가 t+1 에 체결**합니다. 판단한 날 종가에 체결하면 이미 알고 있는 그날 움직임을 먹습니다.
- `quotes[].daily` 가 아니라 `dailyCache` 원본을 씁니다. `loadQuote` 가 마지막 봉을 현재가로 덮거나 오늘 봉을 덧붙인 사본이기 때문입니다.

**우연과 비교합니다**
- 그냥 보유와 바로 판정하지 않습니다. 덜 들고 있는 규칙은 오르는 종목에서 수익이 낮고 낙폭이 작은 게 당연해서입니다.
- 20/60 은 **판단 열을 62칸 이상 돌린 가짜 타이밍 200개**와 견줍니다. 보유 비율과 매매 횟수는 그대로이고 시점만 엉뚱해집니다. 20일선 − 60일선은 최근 59일 등락으로만 정해지므로 62칸보다 덜 돌리면 가짜 규칙이 자기 구간 등락을 미리 봅니다.
- 판정 끝은 **1%** 입니다. 돌린 200개는 이웃끼리 거의 같아 독립인 비교가 20개 남짓이라, 2.5% 로 두면 무작위 걸음 600개 중 7.5% 가 나음/못함으로 걸렸습니다. 1% 에서 5% 였습니다(2026-10-12 실측).
- 배열 국면은 **하루하루 등락을 평균 10일 덩어리로 섞은 가짜 주가 200개**에서 이평선부터 다시 계산한 차이와 견줍니다. 양쪽 2.5%(200개면 위아래 5개씩) 밖이면서 앞 · 뒤 절반의 차이 방향이 같을 때만 판정합니다. 무작위 걸음 180개에서 10개(5.6%)가 걸렸습니다.
- 난수는 종목 코드로 시드를 정해(FNV-1a → mulberry32) 볼 때마다 같은 결과가 나옵니다.

**툴팁이 말하는 것** (2026-10-13 재검증 뒤)
- 20/60 순위는 개수로 보입니다: "가짜 타이밍 200개 중 규칙보다 누적이 낮은 것 N개 → 판정 (198개 이상이면 나음 · 2개 이하면 못함)". 백분율("상위 99%")은 반올림 때문에 못함에도 구분 안 됨에도 같은 값이 나왔습니다.
- 배열 국면의 차이와 범위 끝은 소수 한 자리로 보이되, 둘이 같게 보이면 셋 다 둘째 자리까지 보입니다. 신한지주(2026-10-13)는 차이 +3.18%p · 위쪽 끝 +3.21%p 가 둘 다 "+3.2%p" 로 보여 왜 "안" 인지 알 수 없었습니다.
- 끝에 두 줄을 둡니다. 효과 없는 규칙에서도 판정마다 20번에 1번꼴로 나음 · 못함이 나온다는 것(실측 4~5%), 그리고 지난 기간의 설명이라는 것입니다. 10년치 90종목에서 앞 5년 20/60 순위와 뒤 5년 순위의 상관이 -0.02 였고, "20거래일 뒤 중앙값" 의 방향 적중은 50.9% 였습니다.
- Windows 의 Chromium 은 툴팁을 1024자에서 자릅니다(`ui/views/corewm/tooltip_state_manager.cc` `kMaxTooltipLength`). 실데이터 99종목 중 가장 긴 툴팁이 767자(코스피)입니다. 줄을 더하면 `session-ui` 의 길이 검사를 보세요.

**표본**
- 확정 봉 500개(약 2년) 미만이면 계산하지 않습니다. 국내 종목에 하루 **35%** 를 넘게 움직인 봉이 있으면 액면분할 같은 데이터 이상으로 보고 그 뒤만 씁니다. 그 뒤로 500개가 안 되면 "데이터 확인 필요" 입니다.
- 문턱이 가격제한폭(±30%)이 아니라 35% 인 이유: 진짜 상한가 · 하한가 날이 30% 를 조금 넘게 나옵니다. 정확히 +30% 도 부동소수로는 0.30000000000000004 이고, 야후 전일 종가가 기준가와 한 틱 달라 +30.2% 가 되기도 합니다. 30% 로 두었을 때 에코프로비엠(2023-11-06 상한가)은 "3년" 으로 잘리고 한화오션(2024-11-08)은 "데이터 확인 필요" 가 됐습니다(2026-10-12, 74종목 실측). 대가로 0.5주 무상증자(-33%)처럼 30~35% 사이의 데이터 이상은 놓칩니다.
- 0 이하 · 숫자가 아닌 종가는 빠진 봉처럼 버립니다(`usableSeries`). 섞이면 수익률이 Infinity · NaN 이 되어 툴팁이 NaN 으로 차고 엉뚱한 "못함" 이 났습니다 — 해외 종목은 35% 검사도 없습니다. 실데이터 99종목에서는 결과가 바뀌지 않았습니다(2026-10-14).
- 진입 5회 미만이면 표본 부족입니다. 5년에 20/60 진입은 보통 10~15회라 승률은 보이지 않습니다.
- 배열 국면 툴팁에는 일수와 함께 "겹치지 않는 20일 묶음 수" 를 적습니다. 214일이라도 서로 독립인 경험은 10번 정도입니다.

**비용과 계산 시점**
- 왕복 비용은 국내 종목 0.25%(매도세 포함), 해외 종목 · 지수 0.10%(지수는 ETF 로 따라간다고 봄). 배당 · 세금 · 환전은 넣지 않습니다.
- 한 종목에 약 50ms 입니다(1,231봉, 2026-10-12 실측). 선택한 종목만, `trendCache` 에 (봉 수, 끝에서 두 번째 봉 시각)으로 캐시해 마지막 확정 봉이 바뀔 때만 다시 계산합니다. 30초 갱신 · 일봉 재수신은 마지막 봉만 움직이므로 다시 계산하지 않습니다.
- 계산이 예외를 내면 줄만 숨기고 콘솔에 남깁니다. 그대로 두면 `renderDetail` 이 거기서 끊겨 그 갱신의 합계 줄 · 차트까지 빠집니다. 실패도 캐시해 같은 확정 봉으로는 다시 계산하지 않고, 다음 봉에서 다시 해 봅니다.
- 줄의 상태는 `20선>60선 34일째`(아래면 `20선<60선`)입니다. 처음에는 `20/60 보유` · `정리` 였는데, "보유" 가 사용자의 실제 보유(목록 · 상세)와 같은 말이라 바꿨습니다.
